# 本地离线口上（AIRP）脱机游玩独立模式工程架构与实施方案

> **设计核心原则**：
> 1. **纯粹二分，拒绝静默降级**：在线云端 API 模式与脱机离线口上模式严格独立并列，**绝不进行在线网络错误（429/503）时的自动静默降级**，保持错误状态的透明性与可预期性。
> 2. **意图明确，即开即玩**：玩家在标题界面「API 配置」中自主选择模式。选择脱机模式后，完全不发起任何网络请求，直接调用全岛 49 位角色的本地离线口上库，零延迟、零 Token 开销。

---

## 一、 背景与现状剖析

### 1. 当前运行现状
* 目前底层已经完整实现了 31 套高频核心语义模板、317 条预烘焙特征向量，以及覆盖全岛 49 位可互动角色的专属 Wildcard 词库。
* 在之前的逻辑中，当在线 API 遇到 HTTP 429（超频限流）或 503（服务繁忙）时，系统未弹出本地口上。经排查，这是因为工程中存在自动化测试 `test_free_dialogue_retry_behavior.gd`，其严格要求在线 API 报错时如实向玩家展示错误原因，并提供「重试」交互。

### 2. 为什么必须“拒绝在线自动降级”？
* **认知失调**：如果玩家配置了在线大模型（如 DeepSeek、Claude、GPT），在 API 故障时系统如果偷偷偷换成离线模板，玩家会误以为大模型“上下文崩塌”、“格式错乱”或“严重失忆”，从而产生极大的困惑。
* **知情权剥夺**：玩家无法获知自己的 API 密钥是否欠费、额度耗尽或端点失效，剥夺了用户排查连接问题的知情权。
* **工程契约破坏**：在线重试机制与离线确定性响应应该边界清晰，各司其职。

## 二、 模式二分化设计方案

系统将自由对话通道划分为两种平行的顶层运行模式：

```
                              【自由对话运行模式】
                                       |
                   +-------------------+-------------------+
                   |                                       |
          【模式 A：在线 API 模式】                 【模式 B：脱机游玩模式】
                   |                                       |
          读取 URL / Key / Model                无需任何网络与密钥配置
                   |                                       |
            发起网络 HTTP 请求                     100% 纯本地离线运行
                   |                                       |
       +-----------+-----------+                           |
       |                       |                           |
   [调用成功]              [网络/429/503报错]              |
       |                       |                           |
  流式呈现大模型生成       如实呈现错误状态与重试按钮      直接调用 LocalAIRPClient
                         （绝不静默偷换离线口上）        （全岛49位角色专属反馈）
```

## 三、 各模块详细技术改造清单

### 1. 数据模型与配置持久化（`scripts/ai/game_llm_client.gd`）

#### 配置项扩充
* 配置文件路径：`user://llm_client.cfg`
* 新增自由对话专属配置字段：
  ```ini
  [dialogue]
  offline_mode = true ; true 为脱机游玩模式，false 为在线 API 模式
  ```

#### 逻辑判断改造
1. **配置检查 `configured()`**：
   * 若 `channel == DIALOGUE` 且 `profiles[DIALOGUE].get("offline_mode", false) == true`：
     * **直接返回 `true`**（不需要检查 URL 或 Key 是否为空）。
   * 否则按原逻辑校验 `url` 与 `key` 是否完整。
2. **调度派发 `_dispatch()`**：
   * 若 `route == DIALOGUE` 且 `profiles[DIALOGUE].get("offline_mode", false) == true`：
     * **直接调用 `_dispatch_local_airp()` 并立即返回**。
     * 绝不创建 HTTP 请求节点，彻底隔离网络开销。
   * 若 `offline_mode == false`：
     * 正常通过 `_transport.start()` 发起网络请求。
     * 若网络返回错误（包括 429、503、超时、DNS解析失败等）：
       * **严格调用 `_complete(error)` 报告错误，绝不回退至 `_dispatch_local_airp()`**。
3. **保存接口 `save_profile()`**：
   * 接口参数增加 `offline_mode: bool = false`。
   * 当保存 `offline_mode == true` 时，允许 `url` 和 `model` 留空，避免强制校验报错。

---

### 2. 用户界面交互设计（`scripts/ui/title_api_settings.gd`）

在标题界面的「API 配置」弹窗中，对「自由对话」页签进行针对性重构：

#### 界面控件布局
1. **顶层模式切换开关**：
   * 在「API 基础地址」上方新增复选框或模式切换卡：
     * `[X] 开启脱机游玩模式（使用全岛 49 位角色本地离线口上）`
2. **动态响应与控件联动**：
   * 当勾选「开启脱机游玩模式」时：
     * API 基础地址（`_url`）、模型 ID（`_model`）、API 密钥（`_key`）、获取模型按钮（`_fetch_button`）自动变为只读不可编辑状态（或半透明灰色）。
     * 状态提示栏（`_status`）显示清晰绿色说明：
       `已启用脱机游玩模式 · 全岛 49 位角色离线口上库就绪 · 零延迟无需网络`
   * 当取消勾选时：
     * 恢复在线 API 输入框的编辑状态，供玩家配置云端大模型服务。

---

### 3. 游戏内对话面板与状态反馈（`scenes/narrative/dialogue_panel.gd`）

* 在游戏内与 NPC 自由对话时：
  * 若处于**脱机模式**：对话输入栏上方或状态标签轻量显示 `[本地口上]`，让玩家明确知道当前是 49 位角色的专属离线文本。
  * 若处于**在线模式**：正常展示云端模型推理状态；若遇到 429 / 503，面板底部显示 `[接口限流/繁忙，点击重试]`，保持体验纯净。

## 四、 实施计划与验证步骤

### 步骤 1：底层核心配置与派发逻辑改造
* 在 `scripts/ai/game_llm_client.gd` 中：
  * 实现 `offline_mode` 的存取与默认值处理。
  * 改造 `configured()`、`save_profile()` 和 `_dispatch()`。
  * 移除 `_receive_result()` 中的任何潜在降级旁路，坚决贯彻“在线报错即如实报错”原则。

### 步骤 2：标题界面设置项接入与持久化
* 在 `scripts/ui/title_api_settings.gd` 中：
  * 添加 `_offline_mode_check: CheckBox` 控件与界面联动逻辑。
  * 确保保存时正确写入 `offline_mode` 到配置文件。
  * 打开设置界面时正确读取并恢复勾选状态。

### 步骤 3：编写 Godot 引擎自动化验证测试
* 创建专门的自动化单测脚本 `tests/test_offline_play_mode.gd`：
  1. **测试 A（脱机模式直通）**：设置 `offline_mode = true`，清除 URL 与 Key，发送消息，验证 0 毫秒直接产出本地口上气泡，`history` 记录完整。
  2. **测试 B（在线错误绝不降级）**：设置 `offline_mode = false`，模拟远程端点返回 HTTP 429，验证系统产生明确的 `error` 状态且没有本地口上插入，重试流程顺畅。
  3. **测试 C（全岛 49 角色在脱机模式下无差别调用）**：随机抽取 10 名不同流派角色，验证在脱机模式下均能正常响应，零省略号，零空回复。

## 五、 方案效益总结

1. **零学习成本与开箱即用**：新玩家或单机玩家不需要了解任何 API、Base URL、Token 概念，只要保持默认或勾选脱机模式，全岛 49 位小姐姐立刻生动鲜活。
2. **极客玩家体验不受损**：自建 API 的进阶玩家，在面对服务器超频或欠费时能够一眼看清真实报错，便于针对性调整大模型参数或充值，不再有被偷换模板的困惑。
3. **系统架构高内聚低耦合**：在线模块只管 HTTP 通信与流式解析，离线模块只管特征向量检索与 Wildcard 组装，两者互不污染，维护极其轻量。
