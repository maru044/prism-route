# 本地离线口上（AIRP）脱机游玩独立模式工程架构与实施方案（修订版）

> **修订说明**：
> 本版本严格采纳审查意见，将来源选择提前至请求准备阶段、明确会话历史与云端上下文隔离边界、规范真实游戏入口与多轮操作（重试、续写、撤回）、校正导出包离线性能评估指标，并建立确定性的全角色资源完整性与增量可维护性校验。
> 全文严格遵守零省略号法则。

---

## 一、 核心设计原则与架构契约

1. **请求准备阶段固定来源，纯粹二分**：
   * 在回合生命周期开始时的 `_can_start()` 与 `_start()` 阶段，即根据设置锁定本次会话来源（`cloud_api` 或 `local_airp`）。
   * 选用本地模式时，直接进入本地检索与组装流程，跳过云端世界书加载与上下文 Token 预算切片。
   * 选用云端模式时，遇到配置缺失、传输启动失败、HTTP 429、503 或超时，均在统一的错误契约下如实报告原因并提供重试，**坚决不执行任何自动静默降级**。
2. **设置透明与数据隔离**：
   * 标题设置统一命名为「自由对话来源」，提供「云端 API」与「本地口上」两个平行的第一类来源。
   * 切换来源时完整保留已填写的云端 API 配置字段（URL、Key、Model）。
   * 会话历史与草稿按角色和来源分别隔离存储，确保本地回合数据绝不泄露至云端请求上下文中。
3. **真实游戏入口驱动与多轮控制**：
   * 明确大世界、家园起居与战斗对峙三大入口的状态注入规范。
   * 规范本地模式下的多轮对话控制：支持承接上一句、支持明确停止与暂停、定义本地重试（施加模板命中惩罚）与本地续写（追问插槽扩充）。
4. **确定性资源校验与增量可维护**：
   * 废除缺省静默回退至花火词库的容错机制，建立 49 位角色的强一致性资源校验。
   * 验证仅通过新增文本素材与重新烘焙嵌入索引，即可零引擎代码扩充新场景口上。

## 二、 模式架构与请求生命周期流转

```
                                【自由对话启动请求】
                                         |
                  【准备阶段：_can_start() / _start()】
                     检查 dialogue_source 配置与会话键
                                         |
                     +-------------------+-------------------+
                     |                                       |
           [来源：云端 API 模式]                    [来源：本地口上模式]
                     |                                       |
           校验 URL / Key 完整性                   直接进入本地准备流程
           加载云端世界书与 Token 预算             （跳过世界书与云端预算）
                     |                                       |
             发起 HTTP 传输网络请求                 调用 LocalAirpClient
                     |                                       |
         +-----------+-----------+                  BGE 向量检索 + 角色词库
         |                       |                           |
     [HTTP 成功]             [异常报错]                [产出自然语言口上]
         |                       |                           |
    流式呈现正文           统一错误契约处理             填入历史气泡与近期抑制
                     429/503/超时/启动失败                   |
                     如实呈现状态与重试按钮             完成回合，记录耗时指标
                    （绝不静默降级为本地）
```

## 三、 详细技术改造规范

### 1. 来源前置与调度重构（`scripts/ai/game_llm_client.gd`）

#### 配置持久化与默认行为
* 配置文件：`user://llm_client.cfg`
* 配置键：`[dialogue] source = "local_airp"`（取值为 `"cloud_api"` 或 `"local_airp"`）。
* **版本迁移与默认规则**：
  * **新用户首次进入**：默认设置为 `"local_airp"`（本地口上），实现无需网络和配置即可开箱即玩。
  * **老用户迁移**：若配置中已有非空的 `url` 和 `model`，保持为 `"cloud_api"`，尊重既有设定。

#### 生命周期改造
1. **准备与就绪判定 `_can_start()`**：
   * 若 `dialogue_source == "local_airp"`：
     * 仅检查本地检索器与词库就绪状态，直接放行，**跳过 `_load_dialogue_markdown()` 云端世界书读取**。
   * 若 `dialogue_source == "cloud_api"`：
     * 检查世界书与 API 配置。
2. **初始化执行 `_start()`**：
   * 若为本地来源：构建本地上下文与角色会话状态，直接调度 `_dispatch_local_airp()`。
   * 若为云端来源：计算上下文 Token 预算与提示词切片，进入网络传输流程。
3. **彻底清理静默降级旁路**：
   * 移除 `_dispatch()` 中关于启动失败转本地的兜底逻辑。
   * 云端连接启动失败、HTTP 429、503、网络超时一律走 `_complete(error)`，将实际原因如实返回面板。

---

### 2. 界面接入与历史隔离（`scripts/ai/llm_panel.gd` 与 `title_api_settings.gd`）

#### 标题设置面板（`title_api_settings.gd`）
* 配置界面标题：**「自由对话来源」**。
* 控件形式：单选按钮组（`ButtonGroup`），包含：
  * `● 本地口上（全岛49位角色专属离线口上，无需网络，断网可用）`
  * `● 云端 API（自定义大模型接口，需配置服务地址与密钥）`
* **字段保留与交互联动**：
  * 切换到「本地口上」时，原有的 API 地址、密钥与模型输入框变为不可编辑的禁用状态，**原有填入的文本完整保留**。
  * 状态标签显示：`已选择本地口上 · 全岛 49 位角色词库就绪 · 离线可用`。
  * 切换到「云端 API」时，恢复输入框交互能力。

#### 会话隔离与操作边界（`llm_panel.gd`）
1. **会话键隔离（Session Keys）**：
   * 会话历史存储键规范为：`channel + "/" + character_id + "/" + dialogue_source`。
   * 本地模式的历史与云端模式的历史互不干扰，保证本地对话记录绝不会作为上文污染云端提示词。
2. **本地模式下的操作行为定义**：
   * **重试（Retry）**：以当前玩家输入重新触发检索，对最近一次命中的模板施加 `-0.20` 的选择惩罚，引导生成同场景下的差异化变体。
   * **续写（Continue）**：在当前回复末尾追加角色的后续追问或情境动作，不重新检索主干模板。
   * **撤回（Undo）**：从本地会话队列中弹出最后一回合，恢复先前的界面状态。

### 3. 游戏实际入口与场景状态规范

游戏内各大入口在唤起自由对话时，需向 `context` 明确注入所处场景与物理状态：

| 游戏入口场景 | 对应入口脚本 | 注入场景标识 `scene_id` | 状态字段注入规范 |
| :--- | :--- | :---: | :--- |
| **大世界初遇与探险** | `sparkle_tutorial_dialogue.gd` / 大世界互动点 | `home_chat` | `dialogue_location = 地点名`, `current_interaction_state = "日常闲聊"` |
| **家园起居与亲密互动** | `dialogue_panel.gd` / 居住区家具 | `home_chat` 或 `intimate` | 结合好感契约注入：`intimate_mode = true/false`, `bound_furniture_info = 家具名` |
| **战斗决斗与侍奉对峙** | `npc_world_duel.gd` | `combat_h` | 结合对战状态机注入：`pleasure_npc = 数值百分比`, `combat_state = "surrender/restraint"` |

#### 多轮场景验收矩阵
* **场景 A（未见过的同义表述）**：玩家使用生僻或方言化的表达（如“歇会儿吧”），系统能准确归纳至对应意图模板。
* **场景 B（承接上一轮情境）**：在亲密模式下，接续上一轮动作表达“再快一点”或“轻柔一点”，反馈连贯不突兀。
* **场景 C（明确停止与暂停）**：玩家输入“先停一下”、“今天就到这里吧”，准确命中暂停或事后温存模板，角色主动退出激烈动作并予以安抚。
* **场景 D（低置信度澄清）**：输入完全脱离当前情境的高难度超纲内容时，角色以符合人设的口吻进行疑惑澄清，并友好引导回归场景。

### 4. 导出包离线验证与性能真实性保障

1. **废止夸大性宣传表述**：
   * 正式技术文档全面废止“零延迟”、“即点即就绪”等不客观表述。
   * 性能标准以实测数据为准：
     * **冷启动耗时**：探针进程拉起与模型权重映射耗时（预期 150ms 至 300ms 之间）。
     * **热响应耗时**：已常驻探针情况下的单次特征提取与检索耗时（预期 10ms 至 30ms 之间）。
2. **导出包断网验收规范**：
   * 使用 Windows 导出包进行完全断开物理网卡的离线测试。
   * 验证打包目录中的随包侧车、BGE 模型权重、参考向量索引与 49 份词库能够正确加载。
   * 验证探针拉起期间 Godot 主线程渲染循环保持响应，界面不卡死。
   * 模拟异常场景：当模型文件人为缺失或探针崩溃时，向玩家抛出友好的错误诊断信息，绝不发生进程崩溃闪退。

### 5. 资源完整性约束与增量扩充验证

1. **确定性全名单强校验**：
   * 重构 `scripts/ai/local_airp/local_airp_composer.gd` 中的词库获取逻辑：
     ```gdscript
     func get_character_data(character_id: String) -> Dictionary:
         if character_wildcards.has(character_id):
             return character_wildcards[character_id]
         var path := data_directory.path_join("wildcards_%s.json" % character_id)
         if FileAccess.file_exists(path):
             var custom_data := _load_json(path)
             if not custom_data.is_empty():
                 character_wildcards[character_id] = custom_data
                 return custom_data
         push_error("Missing dedicated wildcard data for character: " + character_id)
         return {} # 严禁缺省退回花火词库
     ```
   * 编写专用校验脚本，确保名册中所有 49 位角色严格拥有专属词库文件，且必须通过无省略号断言。
2. **数据驱动的增量扩充验证**：
   * 执行一次标准增量维护实验：
     1. 在 `templates.json` 中新增 1 套语义模板与对应参考问法。
     2. 运行 `tools/build_airp_embeddings.py` 刷新 `reference_embeddings.json`。
     3. 在不改动任何 GDScript 逻辑的前提下，重新打包并运行，验证新问法能否通过实际入口精准触发。

## 五、 最终交付验收条件

以玩家的真实断网游玩体验为最高准则：
1. **玩家体验闭环**：在标题设置中选用「本地口上」后，断开全机网络，进入游戏可在支持的场景中与全岛 49 位角色顺畅交流，对话能够承接上下文，也可以明确叫停并进入安抚休息，回复质量符合人设。
2. **错误透明契约**：选用「云端 API」后，在 429、503 或网络中断时，面板如实呈现具体原因与重试按钮，绝不偷偷替换为离线口上。
3. **长期可维护性**：后续扩充场景和口上，完全依托于修改 JSON 资源与重新烘焙索引，零引擎逻辑入侵。
