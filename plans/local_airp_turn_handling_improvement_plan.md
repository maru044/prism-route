# Prism Route 本地口上改进执行计划

本轮优先解决两件事。玩家明确叫停时立即进入暂停，玩家用短句追问时能接住上一轮话题。之后用少量角色验证完整口上的素材写法，再补检索诊断。沿用现有 BGE 向量索引、角色词库、wildcard 和场景约束，整个流程使用本地素材。

参考项目位于 `D:\角色卡\本地口上测试项目\离线女仆rp`。两边的 BGE GGUF 文件哈希相同，可以直接对照回合处理逻辑。参考项目的现有 12 项回合测试通过。下文把额外对照中发现的漏判也纳入验收。

## P0 明确叫停直接进入暂停

在 `scripts/ai/local_airp/local_airp_client.gd` 把明确叫停放到输入向量提取和模板排序之前，直接选用当前角色可用的暂停口上。保留现有识别正确的表述，补上「到此为止」「不要继续」「别继续了」等组合。判断短语及其否定关系，移除单凭出现「停」字就判定暂停的规则。若一句话同时表达「先等一下」和「再继续」，先暂停本轮，等新的明确指令再恢复。

当前游戏会话如果已经绑定了可停止的实际互动，沿用该互动的停止流程。纯对话更新本地回合状态即可。暂停模板的选择不受语义分或去重惩罚影响。参考实现见参考项目 `scripts/ai/local_airp/turn_context_parser.gd` 的 `is_strict_stop()` 和同目录 `local_airp_client.gd` 的暂停分支。

| 回归输入 | 预期 |
| --- | --- |
| 到此为止，不要继续。 | 本轮进入暂停 |
| 别继续了。 | 本轮进入暂停 |
| 我改变主意了，到这儿就好。 | 保留现有正确的暂停判定 |
| 等一下再继续。 | 本轮先暂停 |
| 不要停。／继续吧。 | 交给常规检索或当前场景的明确恢复流程 |
| 停电了吗？ | 按普通提问处理 |

在实际 `GameLLMClient` 本地发送路径覆盖普通场景和原先误判的亲密场景，断言暂停标签和回合结果，并确认明确叫停的请求无需向 BGE 发送向量提取指令。

## P1 让短句承接本地会话里的上一轮

从 `scripts/ai/game_llm_client.gd` 的本地派发入口，将上一条有效回复的话题标识和少量相关状态交给检索器。参考项目的 `build_augmented_query()` 已演示如何补全短句。Prism Route 可以根据话题适度收窄候选模板，也可以为检索查询补入由素材定义的话题描述。规则和参考问法应与口上一同维护。

- 按角色和本地会话保存或从当前生效的回复重建话题。只有有效回复更新话题，澄清和运行错误保留前一个有效话题。暂停状态单独处理。
- 「那个呢」「照刚才那个做」「换一种」这类需要指代的短句才借用上文。玩家明确切到新话题时，按本轮内容检索。缺少可用前文时，用角色口吻追问。
- 重试后以玩家选中的回复为准，撤回后恢复到上一有效回合。处理读档、换角色和切换来源，本地话题状态只供本地检索使用。

**验收**用一条相同的短句分别接在两个不同的现有话题后，验证命中随前文改变。再用相同短句开启新会话，验证它会澄清。补一条明确转话题、撤回后再追问及切换 NPC 的用例。参考项目的「少放点冰」去掉上下文也能命中同一模板，因此那种用例只能证明模板可检索，不能单独验证承接能力。

## P2 给少量重点场景补完整口上

选一至两位已有角色和两三个常见意图做试点。让作者直接写好主要段落，保留称呼、动作或结尾变化作为 wildcard。沿用 `assets/ai/local_airp/templates.json` 和对应的 `wildcards_<角色 ID>.json`，通过现有角色和场景筛选限制适用范围。

**验收**为同一意图准备新的参考问法和未收录的同义表达。验证两位角色的回应可分辨，动作和后续话题与场景一致。增加或改写素材后，如参考问法变化，运行 `tools/build_airp_embeddings.py` 更新索引。用真实自由对话入口验证素材生效，确认这次扩充由数据完成。长度由场景决定，暂停与澄清保持简短。

## P2 补本地检索诊断

沿用现有的模板 ID、原始分和匹配参考问法，在开发诊断中补上来源、NPC、场景、是否借用上一轮、调整后得分，以及走向暂停、澄清或组件错误的原因。需要排查时才展开实际增强查询和槽位细节。默认日志只保留足够定位问题的元数据。

**验收**各跑一次直接暂停、普通命中、多轮补全、低置信度澄清和探针失败，通过诊断能确认每次走了哪条路径。参考项目的诊断位置是 `scripts/ui/chat_screen.gd` 的回合日志。

## 提交与验收顺序

1. 先提交暂停分流及回归用例，再提交多轮话题处理及回归用例。素材试点和诊断可以分别提交。
2. 用仓库现有的 `tests/test_offline_play_mode.gd`、`tests/test_local_airp_game_runtime.gd` 和 `tests/test_all_roster_airp_dialogue.gd` 作回归。测试应先打开对应对话入口再断言配置，显式选择来源。报告需核对完成标记及断言结果，因为此前 Godot 曾在断言失败后仍返回退出码 `0`。
3. 交付时列出实际运行的用例、预期和观察到的结果，附上素材试点涉及的角色与意图。双人对白和自动换 NPC 留待出现对应玩法需求时再设计。
