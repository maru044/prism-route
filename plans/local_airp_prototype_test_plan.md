# Prism Route 本地 AIRP 替代原型与测试计划

> 2026-11-21 · 供 Gemini 继续测试

## 原型目标

验证玩家在「自由对话」里输入中文后，本地系统能否用当前 NPC 的口吻完成成人角色扮演回复，并在多轮中延续关系、场景、节奏和上一轮动作。首轮目标是让两个角色的两类场景在断网时各自完整走完一段对话，评估这条路线能覆盖多少原本交给远程 AIRP 的回合。地图、传送、攻略和状态查询属于现有「游戏助手」。 [双入口架构](llm_dual_agent_architecture_and_roadmap.md)

复用 Issue #28 准备好的 BGE Q8_0、CPU 执行器和误判分析方法。原来的 24 意图题集测的是工具与玩法问句，另建成人角色扮演题集评估本项目。旧基准中 Q8_0 和官方模型的 Top-1 都是 74.2%，这个结果只用于解释为什么需要用场景状态约束候选。 [Issue #28](https://github.com/maru044/prism-route/issues/28) · [上一轮离线基准](../experiments/local_intent_retrieval/README.md)

## 两条原型路径

两条路径共享同一份角色回复库、同一套场景状态和同一个回复渲染器。先在独立实验目录 `experiments/local_airp/` 中比较，现有自由对话作为人工盲评的参考。

| 路径 | 做法 | 要判断的问题 |
| --- | --- | --- |
| A · 场景规则 | 从场景阶段和明确的玩家意图选对白片段，再从当前角色的变体池挑选 | 规则、状态和少量内容能覆盖多少多轮对话 |
| B · 场景规则加 BGE | 沿用 A 的状态筛选，对剩余候选的代表性问法计算语义相似度 | BGE 能否改善口语、省略、改写和含糊承接的匹配 |

首轮从已有独立 persona 的角色中选两个口吻差异明显的试点，场景采用「家园私下闲聊」和「双方明确进入的亲密互动」。用已有角色设定约束口吻，由编剧准备可直接成句的成人对白片段。每个片段带适用条件、变体和下一轮可承接的话题。见到角色、场景或关系状态变化时，从新状态选择合适的片段。 [角色设定目录](../assets/ai/personas) · [家园闲聊入口](../scripts/narrative/home_interaction_panel.gd)

## 一轮如何产生回复

1. **拿到当前情境。** 实验输入包含 `character_id`、`scene_id`、`phase`、关系状态、最近两轮可见对白、上一轮动作或话题、近几轮已用片段 ID、玩家本轮原文。角色身份和实际场景由固定测试输入提供。后续接游戏时，由 Godot 提供这些值。
2. **筛选当前可用的片段。** 先按角色、场景、阶段和前置条件筛选。用组合后的情境承接「继续」「慢一点」「换个说法」一类短句。明确要求暂停或结束时优先进入对应分支。对不明确的升级请求，用当前角色的口吻问一句，保留已有场景阶段。
3. **选择并渲染。** A 用规则匹配。B 对筛选后候选做 BGE 排序，首轮沿用 512 维 CLS 池化与 L2 归一化，使用同一 GGUF 建索引和编码输入。同一意图的多条例句合并后再比较前两名分差。选中片段后，从可用变体里挑一条并排除最近用过的片段。用固定随机种子复现测试。
4. **写回对白状态。** 返回 `reply_text`、`reply_id`、`intent_id`、`next_dialogue_state`、`confidence` 和 `outcome`。这里的状态只服务于文本连续性。游戏中的动画、数值和操作仍由既有系统触发。低置信度时返回角色内澄清，测试时按「澄清回合」统计。 [对白与游戏状态边界](llm_dual_agent_architecture_and_roadmap.md)

回复库的最小记录含 `reply_id`、`character_id` 或共享标记、场景和阶段、`intent_id`、代表性玩家问法、进入条件、正文变体、后续话题或动作标签。优先准备能独立读通的整段回复。模板字段只填玩家称呼、地点和本轮承接主题等有限信息，减少多段拼接造成的文风断裂。

## 给 Gemini 的首轮测试

### 准备文本和用例

- 每个角色先准备 20～30 个回复片段，每个核心话题尽量有 2～3 个独立变体。共享常用的转场逻辑，两名角色分别写出自己的措辞和反应。语料优先覆盖闲聊转调情、确认与推进、回应玩家反馈、放慢或改变方式、暂停、结束及回到日常。
- 做 **40 条单轮用例和 12 段连续对话**。每段走 6～8 轮，交叉覆盖两个角色与两类场景。将用于建立索引的代表问法、调参对白和最终验收对白按整段会话分开。锁定验收集后用同样的内容比较 A 和 B。
- 每条用例给出当前状态、玩家原文、允许的意图和回复范围、必须延续的前文事实，以及可判断的失败条件。意图只用于定位错误，同一用例可以有多条正确回复。

| 要测的现象 | 用例设计 | 合格表现 |
| --- | --- | --- |
| 承接上一轮 | 同一句「继续」分别接在闲聊、调情和亲密互动之后 | 延续各自刚发生的事，保持所属场景阶段 |
| 具体改动 | 玩家希望「慢一点」或只改说话方式 | 改动对应节奏或措辞，并保留其余上下文 |
| 拒绝和恢复 | 先明确要求停下，之后再主动提出继续 | 停止当轮推进，后续按新的明确请求判断 |
| 人物区分 | 同样的玩家输入用于两个 NPC | 两份回复在用词、反应和称呼上能辨认角色 |
| 切换情境 | 对话中途换地点或换 NPC，再输入「你刚才说的呢」 | 依据新会话的事实回答或澄清，保持角色记忆隔离 |
| 重复与自由表达 | 用口语、省略或不同措辞连续请求同类互动 | 能承接近义表达，同一段对话里有足够变体 |
| 超出库覆盖 | 玩家引入片段库缺少的新情节 | 角色内澄清或回到当前场景可承接的话题 |

### 执行与打分

1. 复用 [离线 BGE 基准脚本](../experiments/local_intent_retrieval/benchmark.py) 和原生探针的编码能力。先实现无界面的回放，读取用例并把每轮的输入状态、候选 ID、命中、使用的变体和结束状态写成 JSONL。代码放在独立实验目录。
2. 单轮用固定历史，确保 A 和 B 看到相同条件。多轮分别从同一起点跑，后续沿用各自生成的历史。固定验收对白和随机种子，记录首次出错的轮次，区分检索选错、库里缺片段、渲染不自然和前文状态丢失。
3. 将 A、B 和已有远程 AIRP 样例匿名排列，按**是否回应这一轮、是否像该角色、是否接得上前文、成人场景文风是否自然**评分。每项用 1～5 分，3 分代表能读通但有明显生硬或脱节，4 分代表可以直接在游戏里使用。优先由熟悉项目角色文风的人复核有争议的样本。

### 进入 Godot 的参考门槛

| 指标 | 首轮目标 |
| --- | --- |
| 可直接使用的覆盖率 | 至少 70% 的场景内验收回合可直接使用。合格回合的四项盲评分均至少为 4/5，并通过该用例的事实与状态检查。普通澄清回合计入总分母 |
| 人物与连续性 | 口吻和前文连续性各自的中位分至少为 4/5，验收中角色串用和凭空改变场景阶段为 0 |
| 明确暂停或结束 | 所有明确用例都进入对应分支 |
| 重复度 | 连续对话中，同一正文原样再次出现的回合占比低于 10% |

若 A 和 B 都过门槛，选在固定验收集上更稳定、内容维护成本更低的一条。若 B 主要改善检索、盲评仍认为对白生硬，下一轮先补角色对白和可承接的回应。若反复出现「能识别，但库里没有开放情节可用的回复」，再单独评估小型本地生成模型，用相同题集衡量它能补多少覆盖。原型通过后，才将选中的方案接到独立 Godot 场景，验证后台执行、断网可用以及 Windows 导出。
