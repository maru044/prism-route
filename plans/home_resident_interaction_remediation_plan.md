# 家园住客互动验收与修复计划

验收版本 `546f39d`，日期 2026-11-20。范围包括入住后的互动面板、住客行动、闲聊、双人动作的放置与退出，以及这些功能在导出包中的资源可用性。

## 验收结果

现有家园测试通过。另在正式大世界场景用甘雨和现有卧室验证了 G 分配住客、E 互动、跟随、闲聊，以及两个档位的动作进入和退出。两个档位都成功实例化了角色，动作时间也在推进。下表为正式场景无头运行的观测结果，画面中的接触位置和镜头遮挡需在有画面的运行中确认。发布包和真实模型请求尚未复测。 [现有家园测试](../tests/test_home_housing_system.gd#L368)

| 检查项 | 结果 |
| --- | --- |
| 日常侍奉按 E 退出、深度温存按 Esc 退出 | 两次都从荧的第三人称相机切到地图相机。切回后的相机位置距原位置约 521 m。 |
| 互动期间注入移动输入 | 两次荧的控制都仍启用。虽然荧已隐藏，约 0.4 秒内仍移动了约 0.52 m 和 0.55 m。 |
| 住客跟随 | 甘雨移动约 0.54 m，仍使用待机资源。重新打开互动面板会丢掉跟随状态，「返回房间休息」消失。 |
| 家园闲聊 | 点击后出现固定台词和好感提升提示。没有打开自由对话，进度数据也未变化。 |

## 动作锚点的根因

项目里有三条相关路径。家园应复用战后 CG 的运行时解析，动作测试场景已有的标定可以作为具体动作的输入。

| 路径 | 当前定位方式 |
| --- | --- |
| 动作测试场景 | 通过预览场景的角色位置和道具标定对齐动作。已有审计给出了将源道具标定反算到世界家具上的方法。 [预览角色偏移](../scripts/character_mmd_vrm_validation.gd#L463) · [坐标换算](../docs/MMD_FURNITURE_ALIGNMENT_AUDIT_20261106.md#L101) |
| 大世界战后 CG | `MotionResolver` 按绑定检查家具及接触、走近锚点，分别算出角色 A、B 的世界变换。战后 CG 再将两份变换分别用于两个角色。 [解析器](../scripts/world/motion_resolver.gd#L6) · [战后 CG](../scripts/world/npc_world_duel.gd#L660) |
| 家园双人动作 | 找到当前房间第一件同类家具后，把同一个接触锚点赋给两个角色，并分别按身高缩放动作位移。锚点缺失会取家具根节点，家具实例缺失会取住客当前位置，仍播放原家具动作。 [家园定位与播放](../scripts/construction/construction_world.gd#L860) |

**可以直接核实的例子是刻晴的桌面动作 `mmd_fca4bab1635f`。** 家园和战后 CG 引用相同的 A、B 两条动画，也使用同名桌面锚点。战后 CG 给两人分别配置了 **−0.838 m** 和 **−0.822 m** 的垂直偏移，家园把两人的动作原点直接放到桌面高度。桌面和椅面的接触高度与人物动作原点属于不同坐标，床沿标记本身也有朝向。仅统一锚点名称仍会留下高度与朝向偏差。 [家园桌面条目](../scripts/construction/home_intimacy_catalog.gd#L243) · [刻晴绑定](../assets/npc/motions/keqing_motions.json#L7) · [建造家具锚点](../scripts/construction/basic_kit.gd#L43)

| --- | --- |
| P0 | **相机和输入退出有问题。** 开始互动时没有保存当时的相机，结束时硬切到 `world.camera`。家园也没有接入世界的演出控制上下文，所以界面报告输入锁定时，角色控制器仍可移动。当前环绕镜头还缺少对室内墙壁的避让检测。 [开始与结束](../scripts/construction/construction_world.gd#L890) · [大世界控制同步](../scripts/map_1021.gd#L1126) |
| P0 | **动作可选条件和实际播放条件不同。** 菜单按家具类别放行，无法发现锚点缺失、同类家具朝向或实际空间不合适。地面条目直接以住客脚下为起点，跟随出房间或站在墙边时也会放行。目录的 `mmd_7869c66910b9` 源资产包含 A、B、C 三条轨，家园只引用 A、B，需要核准是否适合双人使用。 [菜单过滤](../scripts/construction/home_intimacy_catalog.gd#L381) · [源角色清单](../assets/characters/mmd_selected/manifest.json#L770) |
| P1 | **闲聊仍是占位。** 家园面板写入的是固定台词，且有虚假的数值变化提示。现有自由对话入口已经会用角色 ID 读取 persona，但这一入口接收 `Control` 并绑定遭遇会话。家园面板是 `CanvasLayer`，需要复用打开对话的部分，并提供自己的关闭回调。 [家园闲聊](../scripts/narrative/home_interaction_panel.gd#L337) · [自由对话入口](../scripts/map_1021.gd#L909) · [Persona 加载](../scripts/ai/game_llm_client.gd#L436) |
| P1 | **NPC 行走是直接移动位置。** 初始待机没有启用自动播放，漫游和跟随也没有切换到行走动画。移动逻辑直接改坐标，缺少沿途碰撞与高差处理。结束伴随只会切为待机，界面却宣称住客已返回房间。 [模型初始化](../scripts/construction/home_resident_actor.gd#L55) · [移动](../scripts/construction/home_resident_actor.gd#L131) · [结束伴随](../scripts/narrative/home_interaction_panel.gd#L363) |
| P1 | **打开面板会改掉行动状态，关面板也会覆盖演出状态。** E 会把跟随改成互动状态，关闭后重置为待机。选动作还同时走旧通知和新演出两条回调，旧通知会重新按房间家具分类，导致提示与实际动作不一致。G 和 E 面板打开时实测角色控制仍启用。 [E 与旧回调](../scripts/construction/construction_world.gd#L770) · [关闭面板](../scripts/narrative/home_interaction_panel.gd#L172) · [动作按钮](../scripts/narrative/home_interaction_panel.gd#L292) |
| P1 | **家具刷新可能继续读取旧房间记录。** 房间 ID 和住客都相同时会保留现有实例，但没有更新它缓存的家具和格子。已有住客的房间后续添置或替换家具时，需要用当前建造数据重新计算可用家具与有效落脚区域。 [住客刷新](../scripts/construction/construction_world.gd#L1004) · [菜单读家具](../scripts/narrative/home_interaction_panel.gd#L321) |
| P1 | **资源失败可能换错角色或留下空演出。** 家园用 `FileAccess.file_exists()` 检查导入的 VRM，失败时会把 NPC 换成甘雨或荧。两条动作及角色模型未完成预检就隐藏原角色。源目录里 66 条动作资源均存在，其中 46 条未出现在当前签入的导出预设清单。实际打包是否缺失须按项目的生成流程重新验证。 [家园资源加载](../scripts/construction/construction_world.gd#L832) · [战后 CG 资源预检](../scripts/world/npc_world_duel.gd#L619) · [导出预设生成](../tools/configure_export_1021.gd#L62) |
| P2 | **需要补测房间内可用空间和远处住客的开销。** 当前住客刷新会遍历所有已入住的房间并实例化住客，无距离限制。应检查离开家园后模型和物理更新是否有实际成本，再按测试结果决定是否只保留分配记录、在接近时实例化。 [住客实例化](../scripts/construction/construction_world.gd#L1031) |

## 修复顺序

1. **先修相机、输入和退出。** 进入演出先保存当前 Viewport 相机、玩家状态、住客原行动与鼠标模式。将家园登记到现有世界演出控制上下文，统一锁定角色物理输入。E、Esc、主动取消和异常结束都走同一个清理入口，恢复原相机，原相机失效时由当前游戏模式选择相机。检查室内环绕镜头与墙体的距离。 [世界演出控制上下文](../scripts/world/world_control_context.gd#L25)
2. **统一生产动作定位。** 将家园目录条目转为 `MotionResolver` 可接收的绑定。家具保留自己的接触和走近标记，每个动作带清楚的源参考、A/B 角色映射、局部偏移与朝向。已有战后绑定优先复用并在家园家具上复核，其余用测试场景标定。双人共用播放时间，在保留同一坐标系和角色相对距离的前提下按动作选择位移策略。菜单和开播使用同一套预检。缺少家具、锚点、模型、动作或空间时显示具体原因。若提供地面替代，必须有显式绑定且通过地面检查。第一轮覆盖地面、椅子、床沿、床心和桌面各一项，再逐项开放目录其余条目。
3. **让住客行动独立于 UI。** 标记菜单与演出暂停，关闭后恢复先前行动。启用已有的待机和走路资源，按实际水平速度切换，跟随和漫游共用贴地及障碍处理。跟随停止后安排实际回房，或者在回房能力完成前只显示「结束伴随」。读取实时房间数据，验证建造编辑后家具选择和住客落脚点。
4. **将闲聊接到现有自由对话。** 从遭遇专用入口提取通用打开函数，家园传入当前住客的角色 ID、家园与房间信息，按需提供家具和互动状态。使用 `dialogue` 路由，注入该住客独立 persona，保持自由对话请求无工具。建议沿用 `npc_<角色 ID>` 的会话键，让同一角色在家园及大世界延续对话，换人时切换历史。删掉虚假的好感反馈，关闭对话回到仍有效的家园互动入口。
5. **验证资源与正式入口。** 使用已有的资源检查、导出预设生成和包内审计工具。在实际导出包中按 G、E 测试，确认 NPC 本人加载、两条轨道启动、无缺资源日志，且失败后能继续操作。 [导出验证工具](../tools/verify_export_1021.gd)

## 验收用例

- 两块家园各验证一个房间。原地开始，移动输入应不改变玩家位置，E 和 Esc 都应恢复原探索相机及控制。重复两次并验证异常退出，场景中不能残留演出相机、隐藏的住客或输入锁。
- 用旋转过的桌、椅、床各验证一个已标定动作，同时查看两个角色的朝向以及开始、中段、循环交界时的接触位置。在同一房间放两件同类家具，再用缺锚点、空间不足和删换家具复核菜单状态、选中家具与播放结果一致。
- 住客从待机进入漫游、跟随、停步、重新打开 E 菜单和结束伴随。确认有可见的步态，且不会穿过墙和家具。同一房间添置新家具后，住客无需重新分配即可使用。
- 两名不同 NPC 各发一条闲聊请求。检查首个请求的角色 ID、对应 persona、家园动态标签、独立历史与无工具参数。复测关闭和重新打开、存档读档、取消请求及接口故障。路由和拼装可通过本地请求桩验证。
