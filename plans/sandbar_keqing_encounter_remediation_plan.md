## 一、基线与根因（整改前）

| 问题 | 已确认的现状 |
| --- | --- |
| 待机与衣发物理 | 当前 Avatar 使用 `keqing_fixed.vrm` 和 `shared_world_A01.tres`。直接读取 VRM 元数据，现用模型有 2 条弹簧链、1 个碰撞体组。候选 `keqing_physics.vrm` 有 21 条链、4 个碰撞体组、13 个碰撞体。链数是资产数据，需再检查正式演员的模拟是否运行。现有 A01 的胸、头、脊柱和骨盆旋转各只有一帧，骨盆仍有位移轨道。候选 `koikatsu_idle.tres` 已采用共享人形格式，时长约 4.73 秒，仍需看刻晴正式模型的手腕、站姿和循环接缝。 |
| 物理阻挡与交涉 | 刻晴只有可视演员，缺少常态 NPC 胶囊。提示与触发使用固定出生锚点的 2.6 米球形距离，触发只识别 E。当前 `interact` 只有键盘 E 绑定。花火的现行参考范围为水平 ≤2.8 米、垂直 ≤1.5 米，并有视线射线。家具演出结束时刻晴演员移到了桌旁，提示和碰撞若继续使用旧出生锚点，就会与角色分离。 |
| 战斗演出 | `COMBAT` 目前只显示战斗 HUD。双人演员和专用相机只在家具结算中启用。战斗期间的世界控制已被锁定，新增演出要接入现有相机和角色显隐仲裁；单独调用 `make_current()` 或 `hide()` 可能在世界再次同步时被覆盖。 |
| 桌边浮空 | `desk_01` 的地面和入口是世界 Y=0.100 m，桌面锚点是 Y=0.938 m，高差 0.838 m。两人的角色偏移未配置，当前舞台确实把两个角色根放到桌面锚点。现有集成测试验证了角色变换与 Resolver 一致，因此错误的站位也能通过。 |

## 二、实施路线

### 1. 模型、待机和常态碰撞

- 以 `keqing_physics.vrm` 和 `koikatsu_idle.tres` 作为正式 Avatar 候选，沿用当前材质键。用正式 NPC 演员检查 `ready_for_review`、弹簧模拟实际推进和头发、裙摆、飘带表现，并在相同视角对比原待机和候选待机。观察跨循环的滑步、抖动与手腕。候选不合格时继续沿用原待机并单独处理物理。演员隐藏后使用现有播放控制暂停不再显示的实例，重新出现时恢复。
- 为常态 NPC 增加位值 `64` 的实体胶囊，结合刻晴实际模型和沙洲走道验证容量及净空。以同一个站立根驱动可视演员、交涉判定和碰撞。出生、家具离场、击杀、复活都走同一站位规则。家具离场保留现有桌旁落点的意图，先查落脚与净空，必要时回到已验证的原站位。NPC 在演出或布娃娃状态期间停用常态胶囊，恢复站立时启用。

### 2. 提示与交涉触发

- 居中提示框样式同步覆盖花火与刻晴双场景：交涉文本颜色由原先在明亮沙滩/石地背景下难以辨认的浅黄色统一调整为高对比度的**醒目蓝色**（推荐 `Color(0.4, 0.75, 1.0)` / `#5cb6ff`），字号与居中布局保持一致。提示字样应与 `InputMap` 实际绑定一致，默认仍显示 E。花火神殿（`initial_temple_encounter_controller.gd`）与刻晴沙洲（`npc_world_duel.gd`）使用相同的高对比度蓝色色值。
- 在事件路径使用 `event.is_action_pressed("interact")`，忽略重复键并消费合法交互事件。保持按下单次触发，避免轮询热键和事件处理各触发一次。手柄验收以项目明确配置的绑定为前提。
- 提示显示和实际触发共用站立根、分轴距离、遮挡及世界输入条件。以花火范围作对照，在正式沙洲验证桌边和入口。射线使用正式建筑阻挡层，排除玩家与目标 NPC 自身。设置、自由相机、车载、对话、战斗及演出锁定时禁止开启新交涉。布娃娃拖拽与活体交涉各自消费输入。

### 3. 战斗演出与控制权

- 先打通战斗双人演员、共用播放时间和镜头，再验收与回合、战中对话的衔接。原计划的 `mmd_fcc0340f8227_a/b` 可作为候选，当前已用于 `ground_service`。核对 A/B 角色、循环、脚底支撑、镜头净空和动作适用场景后再确定。战斗放置要有独立的落地入口。当前 Resolver 只对约定的 `ground_service` 走显式地面分支，单独添加一个无锚点的 `combat_service` JSON 键无法直接走现有家具解析路径。
- 使用正式自机荧的模型和材质校准配对动作。选择动作和角色模型后再装配，等两位演员均初始化成功再切换镜头与可见性。资源缺失或装配失败时回到现有普通战斗表现，仍能用 HUD 完成当前对决。
- 用现有世界仲裁管理战斗与家具阶段的镜头、显隐和输入锁，让一次主动的 `_sync_actor_controls()` 保留正确的阶段状态。鼠标运镜、缩放和复位归当前演出所有，对话和 HUD 按键照常被对应面板消费。战中交涉返回仍使用同一场战斗及原轮次规则。
- 退出战斗先停用配对演员与战斗镜头，显示结果对话并保持移动锁。完成结果或家具阶段后，先清理对话、演出和碰撞状态，再发布可游玩状态并同步控制。保留现有故障回滚，去掉结算路径对 `set_control_enabled(true)` 的强行覆盖，让设置等其他仍然生效的输入锁继续工作。重复结算、取消或退出场景只清理一次。

### 4. 桌边动作落地与出口

- 沿用 `Anchor_Desk_Surface` 提供桌面接触基准，`Anchor_Front` 提供通行入口，两位演员的基准站位分别写入 MotionProfile。0.838 米是地板和桌面的高差，`-0.838` 可作为角色根高度的首个试值。脚底和手掌的世界高度还取决于原动作、重定向、角色比例和播放帧。原计划中手脚的采样值与 ±0.3 米水平偏移没有附实机证据，待测量后定稿。
- 在 `desk_01` 的真实地板与桌面碰撞上，用正式模型采样进入、主要接触段和循环交界。分别核对脚底距地、手掌在目标接触段与桌面的距离、桌面可用范围以及身体穿模。最终参数记录角色槽位、局部偏移、朝向和采样结果。以刻晴与荧的模型比例记录本次标定结果。
- 消费 Resolver 已计算的 `role_a_target` 和 `role_b_target`。对子节点设置局部变换或直接设置世界变换均可，采用其中一种写入方式。入口与退出点单独检查支撑和胶囊净空。桌缺失时按现有 `fallback_to_ground` 规则处理，确实切到地面动作时显示对应提示并选取可落脚的退出点；地面也不可用时安全返回世界。

### 5. 复活、重复交涉与资源交付

- 区分玩家败北和 NPC 被击杀后的刷新。玩家确认败北结果时，按本次遭遇的区域与角色 ID 复用 `resolve_battle_respawn()`。沙洲当前映射到 `sandbar_pavilion`。从正式地图已解析的落点取得位置和弧度朝向，确认落点有效后再移动玩家。解析失败时保留安全位置并恢复控制。NPC 被击杀后保留 30 米刷新规则，完成拖拽释放和布娃娃清理，恢复站立模型、同一锚点和碰撞。布娃娃初始化失败时回滚站立与交涉，避免 NPC 长时间消失。
- **三个胜利结算选项都永久解锁刻晴**：「长案侍奉」(`spare_desk`)、「击杀处置」(`kill`)、「点到为止」(`close`)。在确认玩家胜利且选定结算选项后的共用路径调用 `GameProgress.unlock_companion("keqing")`，解锁不依赖各分支演出是否成功。败北和普通对话关闭不触发解锁。使用现有 `companion_unlocks` 随正式存档保存，重复结算不产生重复记录。此项只记录角色解锁进度，正式自机仍只有荧。
- 修复后可反复交涉，无须重新加载地图。初始神殿继续使用现有 `settlement_outcome`；若未来需要持久化刻晴的具体结局，按遭遇 ID 另存，避免覆盖花火进度。
- 更新候选 Avatar、待机与战斗动作的导出依赖。复用 `configure_export_1021.gd` 的 NPC JSON 依赖收集路径核对正式导出清单，要求导出包也能实际加载配置与配对资源。
