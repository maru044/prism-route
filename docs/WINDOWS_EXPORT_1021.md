## 导出范围

Godot 不会自动根据玩家在运行中实际访问过哪些资源来裁剪工程。已新增 `Windows 1021` 预设，选择“所选资源及依赖”，以当前场景和动态加载资源为根；没有采用“所有资源”。[官方导出说明](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_projects.html)。

本工程部分 headless 文件系统缓存没有保存依赖关系，因此 `tools/configure_export_1021.gd` 直接从资源格式、导入场景、脚本文本及全局类解析依赖，显式填写 139 个资源项。程序拼接路径读取的模型、遮罩、七个动作、JSON 和离线草地已明确指定。未来新增动态路径时，应相应更新配置工具中的根资源或非资源过滤器。

没有打入 CAD / Blender 源文件、构建中间文件、文档、截图、历史测试场景或草地分片清单。一个不再被当前草地清单引用的旧格文件仅从导出排除，未删除源文件。必要的当前资源导入结果仍会进入 PCK；这不等于复制整个 `.godot` 编辑缓存。

脚本导出暂用文本模式，因为现有草地签名会读取生成脚本的原始字节。包内这几份脚本、遮罩及材质分类文件已逐字节核对，草地签名保持有效，没有因导出而回退到在线生成。中文文本支持数据已启用并随包导出。

## 复现

```powershell
./tools/export_windows_1021.ps1 -Verify
```

首次运行会将匹配的官方 Windows release 模板下载到忽略目录 `.current_map_build/export_templates/`，只按需读取 TPZ 内的 Windows x64 与 ICU 数据，本次实际下载约 52 MB。换机器后先完成模型导入及草地烘焙，再导出；烘焙数据不在 Git 中。可以通过 `-GodotPath` 指定对应版本的 console 引擎。

发布模板禁用了 `--path` 和 `--script` 覆盖，因此独立检查通过程序内部的 `-- --verify-export` 参数触发。正常双击启动不会运行该检查，也不会改变正常控制。
