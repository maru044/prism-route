# Rhino 崖壁 A / B 资产检查

日期：2026-10-09。检查对象是当时 Rhino 打开的 `D:\Prism Route\map\map.3dm` 中的“崖壁A”和“崖壁B”，不是旧概念方案中编号相同的地形。

## 结论

两者可以继续作为区域级崖壁的建模基础。**B 可以优先进入游戏白模验证；A 应先修复崖顶与相邻地形的接缝。两者都还不是已经通过 Godot 导入、碰撞和材质验证的最终资产。**

本次只检查几何、邻接关系、视图和内存中的网格化结果，没有修改源模型，没有导出新游戏资产。截图后恢复了原视角和显示模式。

## 游戏资产建议

### 1. 明确网格化参数

Rhino 当前显示网格偏粗，尤其 A 的部分三角形最长边约 119 米。这个缓存不是最终 glTF 网格质量的证明；导出时应明确网格化设置。

本次仅在内存中测试了以下起始参数，两者均生成有效网格：

```text
Tolerance = 0.1 米
RelativeTolerance = 0
MaximumEdgeLength = 10 米
MinimumEdgeLength = 0.1 米
GridAngle = 10 度
JaggedSeams = False
RefineGrid = True
```

合计约 5.15 万三角形，只能说明这个底型存在可用的网格化起点，未进行性能测量。实际最大采样偏差 A 为 0.117 米，不能把设置的 0.1 米当作全表面的严格保证。玩家能靠近的崖顶、平台和洞口可先以 2–5 厘米误差为目标局部加密，远处大面保留较粗网格。

### 2. 分块与 LOD

建议沿崖壁先试分成约 100–200 米的连续块，作为初始方案，再按视距、遮挡和场景性能调整。保护相邻块共同边界，避免 LOD 简化后出现裂缝。

Godot 的网格 LOD 距离判定使用节点包围盒的最近点；A 这样的巨型整体靠近玩家时，会影响整块的 LOD 切换。分成独立实例也有利于分别剔除。见 [Godot 4.7 Mesh LOD 文档](https://docs.godotengine.org/en/4.7/tutorials/3d/mesh_lod.html)。

### 3. 开放曲面与碰撞

外侧崖壁用开放网格并不妨碍作为静态关卡碰撞。可用 `StaticBody3D` 加三角网格碰撞；它本质上是空心表面，背面碰撞默认关闭。见 [Godot 4.7 ConcavePolygonShape3D 文档](https://docs.godotengine.org/en/4.7/classes/class_concavepolygonshape3d.html)。

无需为“必须成为封闭实体”把整片区域做成巨大体积。但可进入洞穴、房间和桥接平台需要实际内壁、地面、顶面及局部厚度，并检查朝向。打开双面碰撞不会补出可见的内部结构。

角色、房车能够到达的位置，渲染面与碰撞面应共用基础几何和边界。碰撞简化应保留崖顶、门槛、平台等接缝；本次没有验证游戏内碰撞。

## 美术与探索建议

当前弯曲、非规则的轮廓值得保留，比整齐的小岛排列更适合作为本地图的基础。当前侧壁仍偏连续、光滑，主要像大挡墙或切开的台地；它可以是近未来巨构的底型，但还缺少结构层次和探索入口。

- **A 负责长距离轮廓。** 选少数位置做大尺度断口、风化后露出的骨架、凹入的结构舱。不要沿全线均匀铺满小裂纹或细碎石块。
- **B 可作为局部探索重点。** 先安排一个清楚的中层入口和平台，再决定它是否通过内部通道、少量高架连接另一地形。洞口需要实际建模，不能只靠深色贴图表达可进入空间。
- 两者目前高度范围都是 60 米。保留高处地标，但局部安排低矮收尾、台阶和可停留的中层空间，避免所有路线都只能从底部绕行。
- 强调近未来结构：大尺度壳体、结构肋、设备舱、连接节点及破损覆土。避免把它们处理成古代石砌遗迹；结构细节应服务路线与空间，而非形成密集装饰。

下一轮顺序建议：**A 修接缝 → B 做一个中层探索节点 → 控制网格化并分块 → Godot 验证法线、接缝和碰撞 → 再做材质与 LOD。**
