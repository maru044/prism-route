# Rhino 崖壁 A / B 资产检查

日期：2026-10-09。检查对象是当时 Rhino 打开的 `D:\Prism Route\map\map.3dm` 中的“崖壁A”和“崖壁B”，不是旧概念方案中编号相同的地形。

## 结论

两者可以继续作为区域级崖壁的建模基础。**B 可以优先进入游戏白模验证；A 与相邻地形应先统一接缝。复核显示 A 的崖顶符合现有辅助曲线，不能直接归责于 A 或原始曲线；需要检查地形的成面与修剪边界。两者都还不是已经通过 Godot 导入、碰撞和材质验证的最终资产。**

本次只检查几何、邻接关系、视图和内存中的网格化结果，没有修改源模型，没有导出新游戏资产。截图后恢复了原视角和显示模式。

这些是采样点到邻接曲面的距离，不是连续边界误差的严格上界，也不证明每处都形成空洞。但它们已足以说明 A 尚不能视为无缝拼接。详细坐标见 [audit.json](rhino_cliff_review_2026-10-09/audit.json)。

**复核后的建议：先确定统一的设计边界，再处理地形成面和修剪。** 如果以现有崖顶辅助曲线为准，应让地形边界精确贴合它；如果以最终地形为准，再调整崖顶。此前直接建议重做 A 不够准确，不应在未确认设计基准时单独修改 A。不建议以放大 Join 公差、改法线或材质遮挡代替几何对齐。顶部、崖壁的游戏网格边界也应共享顶点位置；仅 NURBS 曲面贴合不保证各自独立网格化后仍无缝。

### 同日复核：偏差来自什么

用户指出它们应使用相同曲线，因此追加了独立检查，结果见 [seam_recheck.json](rhino_cliff_review_2026-10-09/seam_recheck.json)。本次没有修改任何文档对象，只对内存副本试验。

1. **A 符合现有崖顶辅助曲线。** 对三条崖顶边各采样 501 点，与“辅助线”层中的 PolyCurve `409fe8c0-60a8-4456-b44a-8801880a0a1b` 比较，最大最近距离均小于 `1e-11` 米。另一辅助曲线 `2f7670b2-e6b4-4af9-8724-65a7877cc858` 也在数值精度范围内吻合，最差采样小于 `1.2e-7` 米。
2. **高度偏差发生在曲线与实际地形曲面之间。** “地形”层 PolyCurve `34a6dae0-09e7-4b38-b104-151b72d18e28` 在 A 的边 3、6 上同样吻合（最大采样距离小于 `2.4e-11` 米），但地形曲面不经过部分曲线点。在最大高度偏差处，崖顶/曲线点为 `(280.646818, 1354.570791, 1.325583)`。沿同一 XY 的竖直线与地形求交，地形 Z 为 `0.422348`，高度相差约 `0.903234` 米。这是交线求交的独立复核，不只依赖 Brep 最近点计算。
3. **另一段还存在曲线本身的位置差异。** A 的边 7 与上述“地形”层 PolyCurve 的最大采样距离约 `0.964` 米。在之前的 `0.754` 米偏差点，地形曲线最近点约为 `(786.165809, 205.350453, 60)`，崖顶点为 `(786.879896, 205.109896, 60)`。这段两条现存曲线并非完全同一；该崖顶点在地形未修剪底面上很近，但位于修剪区域外，因此不能把未修剪曲面距离当作实际地形距离。
4. **没有证据表明是简单的缓存边错误。** 对地形的内存副本执行 `RebuildEdges(0.001, True, True)` 后，三个原偏差点的距离约为 `0.194 / 0.903 / 0.753` 米，未消除偏差。这个试验只重建副本边，不修正底面形状，也不改源模型。

因此，之前的距离数值可以复现，且有边曲线比较、竖直线求交交叉支持；它不是“按相同曲线参数取点却参数不一致”的测量错误。但是 **“有偏差”不能直接推出“用户曲线画错”**。更准确的定位是：边 3、6 的现有曲线一致，实际地形成面未严格经过它；边 7 的现存地形边界曲线还与崖顶辅助曲线不同。可能涉及曲面拟合、投影修剪或后来编辑，但缺少建模历史，尚不能确定是哪个命令造成的。

Rhino 的 [Brep.ClosestPoint 官方说明](https://developer.rhino3d.com/api/rhinocommon/rhino.geometry.brep/closestpoint?version=8.x) 说明：最近点落在曲面被修剪掉的区域时，会改查曲面边界。上面的修剪区域内外区别因此需要保留。[RebuildEdges 官方说明](https://docs.mcneel.com/rhino/8/help/en-us/commands/rebuildedges.htm) 说明它恢复的是三维边与曲面的关系，不能把它当作恢复指定设计曲线的成面工具。

A 的两端有约 0.20 / 0.29 米的短边，可能是有意收细的终点。当前显示网格有 30 个长宽比例较差的三角形；定稿网格应复查这些位置，避免细长面集中，而不是直接删除这些端点。

## 游戏资产建议

### 1. 明确网格化参数

Rhino 当前显示网格偏粗，尤其 A 的部分三角形最长边约 119 米。这个缓存不是最终 glTF 网格质量的证明；导出时应明确网格化设置。

本次仅在内存中测试了以下起始参数，两者均生成有效网格：

```text
Tolerance = 0.1 米
RelativeTolerance = 0
MaximumEdgeLength = 10 米
MinimumEdgeLength = 0.1 米
GridAngle = 10 度
JaggedSeams = False
RefineGrid = True
```

合计约 5.15 万三角形，只能说明这个底型存在可用的网格化起点，未进行性能测量。实际最大采样偏差 A 为 0.117 米，不能把设置的 0.1 米当作全表面的严格保证。玩家能靠近的崖顶、平台和洞口可先以 2–5 厘米误差为目标局部加密，远处大面保留较粗网格。

### 2. 分块与 LOD

建议沿崖壁先试分成约 100–200 米的连续块，作为初始方案，再按视距、遮挡和场景性能调整。保护相邻块共同边界，避免 LOD 简化后出现裂缝。

Godot 的网格 LOD 距离判定使用节点包围盒的最近点；A 这样的巨型整体靠近玩家时，会影响整块的 LOD 切换。分成独立实例也有利于分别剔除。见 [Godot 4.7 Mesh LOD 文档](https://docs.godotengine.org/en/4.7/tutorials/3d/mesh_lod.html)。

### 3. 开放曲面与碰撞

外侧崖壁用开放网格并不妨碍作为静态关卡碰撞。可用 `StaticBody3D` 加三角网格碰撞；它本质上是空心表面，背面碰撞默认关闭。见 [Godot 4.7 ConcavePolygonShape3D 文档](https://docs.godotengine.org/en/4.7/classes/class_concavepolygonshape3d.html)。

无需为“必须成为封闭实体”把整片区域做成巨大体积。但可进入洞穴、房间和桥接平台需要实际内壁、地面、顶面及局部厚度，并检查朝向。打开双面碰撞不会补出可见的内部结构。

角色、房车能够到达的位置，渲染面与碰撞面应共用基础几何和边界。碰撞简化应保留崖顶、门槛、平台等接缝；本次没有验证游戏内碰撞。

## 美术与探索建议

当前弯曲、非规则的轮廓值得保留，比整齐的小岛排列更适合作为本地图的基础。当前侧壁仍偏连续、光滑，主要像大挡墙或切开的台地；它可以是近未来巨构的底型，但还缺少结构层次和探索入口。

- **A 负责长距离轮廓。** 选少数位置做大尺度断口、风化后露出的骨架、凹入的结构舱。不要沿全线均匀铺满小裂纹或细碎石块。
- **B 可作为局部探索重点。** 先安排一个清楚的中层入口和平台，再决定它是否通过内部通道、少量高架连接另一地形。洞口需要实际建模，不能只靠深色贴图表达可进入空间。
- 两者目前高度范围都是 60 米。保留高处地标，但局部安排低矮收尾、台阶和可停留的中层空间，避免所有路线都只能从底部绕行。
- 强调近未来结构：大尺度壳体、结构肋、设备舱、连接节点及破损覆土。避免把它们处理成古代石砌遗迹；结构细节应服务路线与空间，而非形成密集装饰。

下一轮顺序建议：**统一 A / 地形的边界基准并修成面或修剪 → B 做一个中层探索节点 → 控制网格化并分块 → Godot 验证法线、接缝和碰撞 → 再做材质与 LOD。**
