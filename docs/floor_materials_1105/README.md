# Rhino 同步与建筑灰色平台排障 · 2026-11-05

当前 Rhino `D:\Prism Route\map\map_current.3dm` 为用户确认的正确版本。本次按该文件同步 Godot，未改 Rhino 几何、未另存完整 Rhino 副本，也未回退角色、道路、地形或水面系统。

## 已确认的问题和修复

初始遗迹三个 `PR_EntryLanding_*` 基座与对应 `PR_EntryLandingCap_*` 的顶面高度、XY 外轮廓相同。深色基座顶面与暖白盖面重叠，造成门外平台呈现灰色。用户已在 Rhino 删除 Lower / Middle / Upper 三块基座，Godot 的旧 `ruin.glb` 尚未同步。

本次同步移除这三个对象，保留其余 325 个对象的位置、法线与索引数据，逐对象核对几何流 SHA-256 一致。三块盖面和六个独立平滑碰撞辅助对象保留；没有靠抬高地板遮住错误。初始遗迹从 6,904 降至 6,868 个三角形。

教堂原生模型使用默认材质来源，游戏端按构件语义绑定材质。43 个石材构件现在复用 `assets/world/cliff_b_test/architecture.tres`；步道保留原石色，主体使用共享暖白。彩玻璃、木材和金属保留专用材质。原主地图中核对到的五个默认建筑物件已正确绑定共享建筑着色器，无需覆盖道路、沙地或地形。

## 同步时不要误伤草缓存

原草缓存签名包含 `metadata.static_features`，直接更新其中的渲染哈希会使既有草缓存失效。此次删除的三个基座仍完整处于保留的种植排除体积内，盖面、其他几何和全部排除多边形不变，因此保留原草生成输入。

当前渲染哈希已正常更新；`metadata.grass_render_only_overrides.initial_ruin_1029` 只为这一次经过验证的渲染修订提供原生成记录。`grass_baked_store.gd` 仅在当前网格和清单哈希均匹配时采用它。后续修改初始遗迹或其他建筑会正常使签名失效，不能照抄本次例外绕过真实地形或种植规则变化。

没有重写草根、随机状态、全图草清单或用户树木存档。运行时草缓存签名仍为 `ba956502a5277980535f7cf593721cb5134809971f52bead4c27ffa765ecd70a`，教堂 12 格局部烘焙继续正常安装。
