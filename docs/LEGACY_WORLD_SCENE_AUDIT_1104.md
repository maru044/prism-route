## 必须保留或先解除依赖

1. **建筑材质。** 正式 `scripts/map_1021.gd`、初始遗迹和椭圆中庭仍加载 `assets/world/cliff_b_test/architecture.tres`；它依赖 `architecture.gdshader` 及三张 `warm_white_architecture_*` 贴图。环庭材质也直接引用这些贴图。因此不能删除整个 `cliff_b_test` 目录。建议先将这组现用资源迁移到正式共享材质目录并更新引用。
2. **旧水着色器。** 正式地图与 `scripts/water/water_manager.gd` 仍引用 `assets/world/map_1012_test/water.gdshader`。这是现用依赖，不属于可随旧模型删除的资源。
3. **植被和车辆的共享实现。** 当前植被继承链为 `tree_planting/world_vegetation.gd` → `map_1021_vegetation.gd` → `map_1012_vegetation.gd` → `vegetation_lod_streamer.gd`，正式房车仍使用 `map_1012_camper.gd` 和 `camper_controller.gd`。它们的命名较旧，代码仍是现用代码。
4. **1012 树木基准。** 本次估算保留了 `map_1012_test/tree_layout.json` 和小型着色器。正式植被会覆盖布局路径为当前地图，但基类默认值和旧验证仍提到该文件；以后可解除默认依赖再决定是否清理。
5. **旧场景之间的入口。** `vegetation_test.gd` 的 Tab 会进入 `world_lod_test.tscn`，植物艺术评审继承它。退役旧岛时需要同步修改入口，避免留下失效跳转；不需要删除共享植物资产。
6. **旧验证与生成脚本。** 1012、Cliff B 等测试有专用验证工具和历史生成工具。清理时应移除失效入口或明确标记退役；`build_landscape_world_mask.py` 等仍可复用的算法代码与几十 MB 的旧构建数据应分别处理。
