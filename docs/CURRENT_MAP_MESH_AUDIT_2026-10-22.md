# 当前 Rhino → Godot 网格审计

结论：当前模型可用于场景验证，但正式游戏资产处理仍有缺口。已经证实的主要问题是运行时绕过导入优化、重复表面、一个朝内闭合网格，以及几乎全量渲染网格直接承担碰撞。不能把所有开放边、三角面或缺少 UV 都当成错误。

本次只新增审计工具、报告和诊断截图；没有修改 Rhino 对象、GLB、地图场景、正式加载器、材质或草地烘焙。

## 检查对象与有效性

- Rhino 当前会话：`D:/Prism Route/map/map_current.3dm`，单位米，绝对公差 0.001 m。
- 263 个 CAD 对象；199 个可见几何均通过 Rhino `IsValid`。
- 对照会话内原始导出 CRC：263 个对象无新增、丢失或几何变化。其他参考曲线不当作网格导出。
- 实际游戏 GLB：199 个对象、5,273,655 个顶点、9,345,058 个三角形，238,875,324 字节。
- GLB SHA-256：`45eae060b42c582dc13143524313c9e8db81388ccee0d4a042a59692a0ee2df1`，保持不变。
- 原始导出缓存与 GLB 的全部 199 件位置、索引逐项完全一致。坐标转换 `(X-1450, Z, 1150-Y)` 为保向旋转，没有引入整体镜像。
- 无非法索引、NaN 坐标/法线、零法线或零面积三角形。没有发现整件顶点及索引完全相同的重复对象，但发现部分表面重复。

## 1. 优先：正式运行时没有使用导入生成的 LOD

`scripts/map_1021.gd::_build_model()` 使用 `GLTFDocument.append_from_file()` / `generate_scene()` 直接解析源 GLB。导入面板的设置不等于这条运行路径上的实际网格数据。

实际查询 `RenderingServer.mesh_get_surface()`：

| 路径 | 网格数 | 有 LOD 的网格数 | LOD 层总数 | 有专用阴影网格的对象数 |
| --- | ---: | ---: | ---: | ---: |
| 当前直接解析 GLB | 199 | 0 | 0 | 0 |
| 编辑器已导入资源 | 199 | 153 | 1,341 | 199 |

其余 46 个导入网格未生成 LOD，不代表它们出错，小网格未必需要简化。专用阴影网格缺失也不是阴影不能工作，表示少了一项可用优化。

1600×900、RTX 5070 Ti、Godot 4.7.2 Forward+，关闭植被，保留地图环境与材质。仅在审计进程中替换现有节点的 mesh 资源；每组预热 35 帧、采样 90 帧，并恢复原网格复测漂移。

| 视角 | 原运行网格：图元 / GPU 中位耗时 | 临时导入资源：图元 / GPU 中位耗时 |
| --- | --- | --- |
| 全景 | 9,345,058 / 2.126 ms | 77,524 / 0.383 ms |
| 西侧开放隧道近景 | 10,150,330 / 约 1.89 ms | 8,120,740 / 约 1.68 ms |
| 北部山坡 | 3,617,332 / 0.974 ms | 1,658,234 / 0.623 ms |

图元是引擎帧计数，可能包含额外渲染通道，不能一律当作唯一可见三角形数。全景 draw call 均为 199，LOD 降低几何量，并没有降低对象提交数量。

表现：远处仍提交细密几何，增加 GPU 顶点处理、内存和加载负担。上述收益是无植被地图部分的实测，不能按比例推算整个游戏 FPS。导入版还同时有阴影网格，收益不能全部归于 LOD。

建议：在独立验证版本中改用导入 PackedScene，保留 UUID 分类及碰撞语义，逐段检查细索、桥壳、洞口和轮廓；通过后再进入正式场景。当前截图只做抽样，不是完整的 LOD 视觉验收。

## 3. 优先：一个闭合路肩整体朝内

`04_洞内连续路肩_1`，UUID `9571ee7f-ce6e-40f7-b13a-d1a647bb9b66`，位于 `交通::隧道`。

- 原 Rhino Mesh `IsClosed=true`、`SolidOrientation=-1`。
- 导出后 1,188 个三角形，闭合、无非流形边、绕序内部一致；有向体积约 -2,668.88 m³。
- 因此这是源网格朝内，并非导出轴转换整体翻转。
- 当前分类 Structure，建筑材质 `cull_back`；碰撞则打开 `backface_collision`。

表现：从外部看，应该朝外的表面可能被背面剔除；人物仍会撞上。这种情况容易被误判为洞口漏面或幽灵碰撞。单纯把材质全部改双面会掩盖方向问题。

建议：只针对确认的闭合壳修正方向，并回归隧道内外观看与碰撞。开放曲面不能按体积正负统一翻转。

## 4. 碰撞网格几乎等于全量视觉网格

运行时生成 197 个凹三角网格 Shape，合计 9,340,098 个碰撞三角形，约为视觉总量的 99.95%。主要仅排除两组斜拉索；水面虽然不承担角色碰撞，也有供查询使用的网格 Shape。

本次 headless 单次审计中，仅 `create_trimesh_shape()` 及背面标记累计约 5.33 秒；不包含加入物理世界的完整登记、GPU 上传、植被初始化和用户最终启动耗时。这是启动阶段成本，不是每帧 5.33 秒，也不是全部三角形每帧都进行碰撞检测。

静态关卡采用凹网格本身是合适的；问题在于没有独立碰撞简化。细密圆角、承托表面、藏在内部的面和重复外壳一起进入碰撞数据。

表现：启动延迟与常驻内存增加；密集几何区域可能增加查询/接触成本，细缝和细碎边还可能影响行走或车辆接地。尚不能根据数量就断言已有所有卡墙问题都由此导致。

建议：建立单独碰撞代理并离线保存；保留车道标高、洞口、拱底净空、台阶与平台边缘，简化小圆角和内部构件。碰撞代理调整会影响草根采样，需要同步校验或重建相关烘焙。

## 5. 局部拓扑与法线异常

以下是对每个对象按完全相同顶点位置进行拓扑合并后的计数，不会实际焊接模型：

| 指标 | 数量 | 主要位置 / 含义 |
| --- | ---: | --- |
| 单物件重复三角面 | 8 | 岛3倾斜廊柱与桥面承托 |
| 非流形边 | 99 | 同一岛3承托对象，UUID `37cde2e1-e1e8-431f-a80a-697f4a61017a` |
| 两邻面绕序不一致的边 | 2,240 | 两组斜拉索、出口小桥低护栏4/5；可能出现端盖缺失或局部阴影异常 |
| 平滑几何处法线差超过20°的边 | 229 | 几何二面角小于10°；集中在分支桥腹及入口连续支撑，有接缝/折光风险 |
| 面方向与平均顶点法线明显对立的三角形 | 545 | 双层桥交织壳、S形地形衔接、沙嘴等；需局部检查，不代表545处可见破洞 |
| 很瘦的三角形，质量指标 <0.001 | 1,036 | 其中960个在两组斜拉索；是质量告警，不自动等同失效 |
| 面积小于1 mm² | 22 | 数量很少，不是当前主要性能问题 |

当前导出先在 Rhino 计算法线，但中间缓存仅保存位置/索引，GLB 构建时再次以三角形面积加权累加法线；没有保留 Rhino 的原始法线数据。该方法可用，但不能自动保留设计所需的连续曲面法线和硬边规则。

建议：保留并正确转换源法线；按物件处理面方向、端盖和局部接缝。不要全图无条件焊接或统一平滑，正常硬边也会被破坏。

## 6. 密度、分块和遮挡处理

- 面数最高的10件占全图约40.25%。西侧中层道路路肩58.50万面、连续底板52.19万面、倾斜拱肩/内壁46.57万面，三件约157万面。
- 现有42个 Mesh 对象直接复制，并不受 NURBS 网格化参数重新控制；5个 SubD 按级别2生成，其余 Brep/Extrusion 才使用4cm公差等参数。因此不能只改一个全局公差就期待全部资产自动变轻。
- 部分地形单件横跨1～2.5km，保持按CAD对象划分。视锥只接触它的包围盒一部分，也可能需要提交整个对象；LOD不能代替空间分块。
- 项目遮挡剔除设置为false；当前地图没有配置 OccluderInstance3D。山体后方、隧道后方的遮挡关系没有作为这条优化管线使用。

表现：远距离看到一小块却提交整个大件；进入隧道后，山体后方仍可能消耗几何处理。Forward+深度预处理能减少不透明片元重复着色，但不会替代对象级的几何剔除。

建议：先解决LOD、重复面和碰撞，再按空间/道路段分块，并对封闭山体与建筑评估简化遮挡体。开阔全景不保证遮挡剔除有收益，不能盲目增加复杂遮挡网格。

## 7. UV、三角化与开放边：目前不应误报

- 源GLB全部199件没有UV0、UV2和切线属性。目前建筑用世界坐标三平面投射，地形用世界坐标遮罩，所以这不会直接导致现有材质错误。
- 以后若使用独立烘焙法线、按物件画纹理或Lightmap，需要相应UV/切线/UV2步骤。运行时 glTF 解析器生成的切线字段不等于建立了有效的贴图展开。
- 全部三角化是正常的游戏渲染方式，不要求游戏最终网格保留四边面。
- 38,954条开放边包含设计中的薄片、洞口、地形边界和独立零件接口，不能当作38,954条裂缝。反之，Rhino `IsValid` 也不能证明没有重叠、朝内或游戏资产性能问题。

## 建议处理顺序

1. 局部修正朝内路肩与六组重合外表面；先解决实际正确性。
2. 独立版本接入已导入资源的LOD和阴影网格，保护建筑轮廓、主桥细索与洞口，做同视角验收。
3. 拆分视觉/碰撞资产，预生成碰撞，回归驾驶/行走及草地采样。
4. 处理局部法线、端盖、非流形承托，再针对高面数大件分块与简化。
5. 根据正式材质与光照方案决定UV/UV2，避免为了“标准流程”重做当前不需要的展开。
