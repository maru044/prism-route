# 通用条凳与建筑内嵌家具制作规范

更新：2026-11-08。适用于新建和修改建筑中的条凳、石台、座椅等可交互部件。**建模阶段必须同时交付可见几何、实际支撑碰撞和定位数据。** 当前脚本与目录的接入缺口见 [家具审计第 7 节](MMD_FURNITURE_ALIGNMENT_AUDIT_20261106.md#7-2026-11-08-建模前复查与遗漏项)；本文是制作契约，不代表导航、交互状态机已经实现。

## 1. 复用原则与适用边界

一组已经标定的单人或多人动作，可以用 **1 个动作参考锚点**定位整个演员组，保留组内角色的相对关系与共同时间轴。每段动作仍需自己的源参考变换和适配范围；一个点不能自动消除动作座高、体型、座面宽度、靠背与墙体差异，也不保证动作库里的所有动作都适用。

**0.420 m 是当前候选通用座高，不是所有动作通用的强制常数。** 批量制作前，先用一张标准条凳和计划使用的动作完成座面、脚底及地面接触验证，再冻结适配规格。同规格户外家具随后复用这份适配，不为每个世界位置重新标定。原有建筑凳座属于按需适配的存量模型，不以本规范追溯认定其制作错误。

普通单槽条凳采用一个 `Anchor_Seat`，无需按动作或角色复制定位点。多人共同动作占用同一个交互槽位；若需要多组 NPC 同时独立坐在一条长凳上，应定义多个独立槽位。长曲凳各处切线朝向不同，不应以整条曲凳的一个中心点代替全部座位。

## 2. 建模尺寸、局部原点与坐标

| 项目 | 制作要求 |
| --- | --- |
| 通用座面基准高 | **距该家具所在的局部完成地面 0.420 m**，指实际可坐表面，不是骨盆骨骼高度、模型包围盒高度或世界 Y=0 |
| 单人小凳参考 | 宽约 0.60 m、深约 0.45 m，仅代表几何参考，不自动支持任意双人组合 |
| 长条凳参考 | 宽 1.20–1.50 m、可用座深 0.45–0.48 m；当前目录规格为 1.40×0.48×0.42 m |
| 家具逻辑根节点 | 位于本家具局部地面、座位中心正下方；局部 +Y 向上、+Z 指向坐者前方，X 为左右。组件内缩放应用为 1，世界实例用平移/旋转摆放 |
| 建筑中的高程 | 楼层位于世界 Y=h 时，座面世界高度应为 h+0.42；不要把高层家具放回世界 0.42 |
| 非标准家具 | 床面、案台等保留独立高度配置；现有床面 0.460 m、桌面 0.838 m，不统一强改为 0.42 |

高差或曲面上的座位需要各自可站立的入口区域与支撑基准。破损、倾斜、太窄或被墙挡住的凳段可保留为装饰，明确不开放交互；不必把所有可见凳段都改造成可坐位置。

标准户外条凳按水平座面、直立根节点制作与摆放，默认只调整水平位置、高程和绕竖轴的朝向。斜坡处通过底座或小平台提供匹配动作的支撑地面；顺坡倾斜整张凳子并不保证预录动作的脚底和重力方向仍正确，需另行适配。

Blender、Rhino 源文件中的高度轴不等于 Godot 的 Y 轴。使用本资产实际导出链的米制单位、轴向和原点变换，导入后测量；不能只看源软件输入值。标记点和几何必须经过同一坐标变换，避免重复转轴、重复扣地图原点或镜像方向。

## 3. 定位点与进出空间

以下坐标均相对于**本家具逻辑根节点**：

| 名称 | 位置/朝向 | 用途 |
| --- | --- | --- |
| `Anchor_Seat`，必需 | 标准条凳 `(0, 0.420, 0)`；语义前方为局部 +Z，yaw=0° | 一组动作的座面参考坐标；不是把所有角色的 Hips 都吸到此点 |
| `Anchor_Front`，有“走过去使用”需求时必需 | `(0, 0, d_approach)`，语义面向座面、yaw=180° | 可站立、可导航到达的入口；d 由家具外轮廓与角色碰撞体确定 |

原规范/当前目录中的 `d_approach=0.50` 只是旧参考值，不是净空保证。直条凳应至少检查 `d_approach >= 前侧实体边界 + 角色胶囊半径 + 余量`。当前世界角色胶囊半径为 0.24 m，0.48 m 深的方凳若从中心计算并预留 0.05 m，所需距离约 0.53 m；制作时可先放在 0.60 m，再检查现场墙体、通道和碰撞。具体仍以实际角色与场地为准。

入口点要有实体地面支撑、角色胶囊净空、可到达通道，以及进入和退出过程的空间。座面上的点不能充当导航终点。仅在原地预览/摆姿的家具可不设入口，但不能因此标记为已支持行走交互。多人动作如需分开的地面入口，应补充相应角色入口点；不受“最多两个点”的旧限制。普通单人离场可复用安全入口，复杂环境再增加离场点。

朝向采用本项目“家具 +Z 为前”的语义约定。Godot 默认 `look_at()` 使用的前轴与此约定不同，接入时显式转换并用导入后的坐向验证。已有 `Anchor_Chair_Front` 是历史动作接触标记，名字里有 Front 不代表它就是经过净空验收的 `Anchor_Front`，也不能直接改名破坏已有配对。

## 4. 建筑内嵌家具与导出交付

```text
Building
  ArchitectureMeshes（允许按原有方案合并渲染）
  FurnitureInteractions
    BenchInstance_001（稳定实例 ID，局部家具坐标）
      Anchor_Seat
      Anchor_Front
    BenchInstance_002
      Anchor_Seat
      Anchor_Front
```

每个可交互家具/槽位有独立逻辑根与稳定实例 ID；`furniture_id` 是目录中的资产类型 ID，不能代替所有实例的唯一标识。不要把一个 `InteractiveFurniture` 挂在整栋建筑根上递归搜所有同名 `Anchor_Seat`：当前实现会让重名项覆盖。

渲染网格可以继续合并，逻辑定位点不必为了交互把全部建筑拆成大量独立网格。建模时保存位置、朝向、所属实例及类型，导出时保留为 GLB 空节点，或明确写入建筑现有 manifest 并由包装场景恢复为节点。**后者尚需对应导入/运行代码支持，不是当前已存在的通用功能。**

2026-11-08 已在 [初始神殿](INITIAL_RUIN_GODOT_1029.md) 实现一个具体范例：CAD 点/方向 → 既有导出脚本 → `manifest.interactions` → 家具独立逻辑根与 Marker3D。其他建筑仍需对应的数据导出和加载代码；该范例当前为 `anchors_ready`，不是通用导航/动作状态机。家具外轮廓可为三角、楔形或其他建筑语言，功能规范约束的是实际可用接触区域、定位与碰撞，不限定长方体外形。

现有上层环庭 Rhino 导出器仅处理 Mesh/Brep，不能直接给它添加 Point/Plane 就认为能自动导出。需要把标记数据与几何记录分开处理，并在重新导出后验证名称、父级、轴向和实例 ID 没有丢失。不要直接手工修改下次会被覆盖的 GLB 作为唯一来源。

## 5. 碰撞、目录和运行时契约

- 座面可见高度、支撑碰撞顶面、`Anchor_Seat` 高度以及目录字段应一致；建模检查可先用 5 mm 以内的差异作为排错目标。靠背、扶手、桌腿与前侧通道还要验证角色和动作包络，不能只比包围盒。
- 复用已有建筑碰撞时不叠加一套同位置家具碰撞。新独立家具应提供合适的简化碰撞。正式世界在运行时将角色 mask 设为 **32（第 6 层）**，新增家具必须同时接入所需角色碰撞层；如还要支持旧地面查询或身体物理，再按既有规则保留第 1 层。不能只因沙盒 mask=1 可碰撞，就认定主世界也正确。
- `-colonly` 不是所有导出脚本都会消费的通用魔法后缀。楼梯按现有管线制作隐藏斜坡，家具按座面实际形状提供碰撞，并确认目标导入器是否已生成碰撞，避免重复或漏建。
- 可实例化的家具目录项应包含有效 `scene_file` 和必要的 `file` 兼容字段、类型、尺寸、表面高度、明确锚点名及坐标。包装场景挂载 `InteractiveFurniture`。当前加载器会访问 `data.file`，只填规范文档不能交付为可加载资产。
- 规格模板、纯装饰家具、已建模但未完成接入的资产，要与已验收交互资产区分。当前目录尚没有完整状态过滤机制；补建模规范并不代表该机制已实现。
- 当前 `get_motion_anchor()` 返回家具根节点局部坐标，已包含中间父级变换；生产调用应精确匹配键并显式处理缺失/重复。当前模糊匹配及缺失时返回单位变换仍是待修问题。
- 家具固定，整组演员采用 `G = F * S * A.affine_inverse()` 定位；A 是动作的源参考变换，不能拿每帧骨盆位置替代。角色进入动画时对 CharacterBody 碰撞、导航暂停和退出恢复的策略由交互逻辑负责，不能用全局关闭碰撞绕过座面穿插。
- 正式入口目前采用资源列表导出；动态读取的目录、动作配对和家具场景还需加入真实依赖与导出规则。文档链接不会自动把家具资源打包进游戏。

## 6. 每次建模交付的最低验收

1. 在 Godot 导入结果中测量局部地面、座面、碰撞顶面和锚点；核对类型、实例 ID、朝向与单位缩放。
2. 对同型家具的两个位置及 90°/180° 摆放做定位检查，家具固定不移动；导入/重导后标记仍可查询。
3. 角色从安全地面入口靠近，确认胶囊不被凳子、墙或栏杆阻挡，并预留离场路径。尚无导航流程时只报告静态净空检查，不宣称 NPC 已能使用。
4. 用实际计划使用的坐姿在起手、接触、循环和退出阶段检查脚底、座面、靠背及衣发；动作参考标定不因家具位置变化而重做。
5. 将可交互状态、适用范围和未通过项目写入该建筑已有说明/manifest，不能以有锚点或截图好看代替完整交互验收。复用原场景、脚本与文档，不为每张凳子新增独立测试目录。

## 7. 从制作指南到可执行交互的交付条件

### 7.1 先冻结一份动作—家具适配记录

一个带朝向的参考坐标系足以定位整组演员，但它不能独自表达动作兼容性。每种已验收的动作与家具规格，至少应保存下列信息到项目实际消费的数据中；**这些是最低语义要求，当前目录尚未实现完整字段与读取流程，不要自行假设字段名已经可运行**：

| 信息 | 必须明确的内容 |
| --- | --- |
| 动作与版本 | 动作 ID、角色位与共同时间范围；重定向、角色偏移及贴地补偿采用哪一份已验证数据 |
| 家具适配规格 | 家具类型、实际支撑面高度与可用座面范围，允许的体型或已验证角色范围；不得只写“所有条凳” |
| 对齐参考 | 明确的 Anchor 名称与源动作参考变换 A，包含位置和朝向；A 在最终播放坐标空间中一次标定，不是每帧追踪骨盆 |
| 接触与空间 | 同时满足座面及脚底/地面接触；记录需要的前侧、侧向和后侧空间，覆盖完整动作轨迹、参与角色与必要的衣发余量 |
| 进出与碰撞 | 每个参与者的入口/离场方案、开始和结束姿势及过渡、交互期间角色碰撞和控制权策略 |
| 验收状态 | 哪些动作—规格组合已经通过，哪些仅为预览标定或尚未验证；不兼容组合不开放使用 |

`G = F * S * A.affine_inverse()` 只能做整组刚性对齐。如果抬高或降低演员组才能贴住座面，却使脚底离地/陷地，说明该动作与家具高度或体型不兼容，不能只以座面贴合宣布成功。优先调整家具规格或换用已经兼容的动作；确需角色接触修正时单独标定并验收，不自动拉伸角色或逐角色破坏原多人相对关系。

### 7.2 运行流程与模型验收分开

可执行流程至少是：检查动作兼容与槽位空闲 → 预约槽位 → 各角色到安全入口 → 完成朝向和进入过渡 → 固定家具、统一定位并共同播放 → 退出到安全地面 → 恢复行走碰撞/控制并释放占用。路径失败、中断或角色离开时应恢复角色状态并释放槽位。多人动作还需同时满足参与者到位与整组占用范围。

建模负责提供满足这些流程的几何、标记、净空和稳定 ID；脚本负责消费数据、导航、状态切换与占用管理。有定位点的模型可称为“交互预备资产”；实际原场景及正式导出包通过上述流程后，才称为“已接通动作交互”。

户外验收还需检查座面和进出区域的草、树干、石块、栏杆及台阶。需要清草时沿用项目原有种植排除与局部烘焙流程，按家具及实际活动范围处理。世界实例摆放后重新检查现场净空；资产本体通过不代表任意位置都可用。

批量化的最小起点是一张标准条凳、实际计划使用的动作和代表角色，在原有验证场景完成一次完整流程，再在正式户外场景验证位置、朝向、碰撞和进出。通过后冻结规格并复用于同类资产；动作、角色比例、座面高度或可用空间超出已验证范围时，再做对应适配。
