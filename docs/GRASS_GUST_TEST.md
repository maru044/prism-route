# 草地 B 大风：小植物场景与 1021 世界（2026-10-25）

入口：Godot 打开 `res://scenes/vegetation_grove_test.tscn`，按 **F6**。
右上角先选「大风」，运动方案默认 **B · 受压草身 + 草尖**。
旧同步正弦仅作为基线保留；用户淘汰的 A 已从菜单、着色器执行分支和录制工具移除。
F5 的 `res://scenes/map_1021.tscn` 现已接入同一 B 大风。左上角面板底部的「草地风力」
可选微风、大风（B）、自动切换；默认自动，24 秒一轮，第 8 秒增强、第 19 秒减弱，
两端各约 3 秒过渡。H/无界面模式也会隐藏这项控件，没有增加快捷键。
想直接对比，可按 2 到南部环塔主桥附近，再选「大风（B）」。默认洞穴出生点保持。

## 当前运动

大风以持续弯折为主，偶尔短暂回弹后重新压弯。宏观风压全场同时作用，不包含麦浪前沿或
逐丛错峰。草身与草尖分开：草身承压，草尖另有小幅快速运动。

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| 持续弯折角 | 85° | 受压状态的草梢切向角，不是整株刚性旋转角 |
| 回弹最小角 | 45° | 回弹时仍保留弯曲 |
| 回弹间隔 | 4.2 s | 每段内全局事件时机略变，无空间传播 |
| 草身响应 | 0.85 Hz | 一次事件约 1.18 s；不是每秒持续大幅循环次数 |
| 草尖细摆 | 2.4 Hz / 4° | 独立于草身响应速度 |
| 梢端后随 | 0.045 s | 沿高度的延迟，不是不同草丛的延迟 |

本次将草身响应从 1.05 调至 0.85 Hz，一次事件从约 0.95 s 延长到 1.18 s，约慢四分之一。
回弹间隔、压弯角度与草尖细摆不变。四阶段仍使用首尾平滑的五次插值。
这些是美术调参，不是实测植物的物理标定。

「参数 / 画质诊断」可调整上述参数和阶段比例，冻结草风或切换 0.25 倍慢放。
少量逐丛/卡片草尖**幅度**差异是可选项，默认关闭，不改变主风压相位。
固定法线、关闭风明暗色带、纯白裁剪、不透明草卡、单张草卡可用于诊断纸片感和闪动。
它们不是正式材质设置。切换基线/B 不重置草时钟；重开场景恢复默认值。

## 几何与隔离

- 模型为 `assets/vegetation/models/grass_star_3card_gust_v7.glb`，保留
  `assets/vegetation/source/grass_star_3card_gust_v7.blend` 和生成脚本。

- B 以四段单位切向积分构造中心线，各段长度为 H/4；不把高度相关角度误代入恒曲率圆弧公式。
  宽草卡保留横向框架，草根固定。基线保留原圆弧方法。
- `GRASS_GUST_DEMO` 作为新草风的可选编译分支，现在由小场景和 1021 使用。
  原树材质、草颜色与透明裁剪策略不变。
  密度仍为 63,000 丛，测试草剔除余量 1.8 m；关闭会消去弯曲顶点的自动网格 LOD。
- 不修改种植分布、草烘焙输入或缓存，不需要重新烘焙。

## 大世界接入

`scripts/grass_wind_world.gd` 在 1021 植物初始化后替换草的显示网格和 shader，并保留原材质的
世界色带、裁剪、距离渐隐与角色交互参数。小场景与世界共用 `grass_wind_settings.gd` 的 B 参数，
避免两个入口的回弹速度漂移。世界面板只有风力选择，不带基线和调参诊断控件。

近、远两组流式 MultiMesh 继续使用原 48–76 m / 76–128 m 密度渐隐。世界新增显示几何 LOD：
近处四段（24 三角形）、中距两段（12）、远处一段（6）。分块按包围盒至相机的最近距离选择，
每 0.1 秒更新并带滞回；shader 在 8–14 m、26–40 m 先把曲线平滑过渡到较粗表示，
几何只在过渡完成后切换。它不改变种植点、实例数量、透明策略、草高和根位置。

大世界还将全场相同的五层中心线与法线集中到 CPU 每帧计算一次，作为四个 vec4 上传；
GPU 顶点读取该曲线，避免每个草顶点重复求四段积分与三角函数。世界草的正交旋转/缩放
使用点积变换，减少逐顶点矩阵求逆。小场景保留原 GPU 计算作为对照。
事件抖动改用确定性的整数种子，确保 CPU 和 GPU 的事件时机一致，未引入空间麦浪。

世界草另用 `grass_world_wind.gdshader` 双面光栅化，每张草卡只存一份几何，删除重复背面。
四段模型为 30 顶点、24 三角形，小场景原 v7 源模型继续保留。UV 保持 glTF 导入方向（根部 V=1）。
最初的正反视角检查只用了环境光，虽然轮廓/贴图最多只有 8 像素超过 3/255 差异，
却遗漏了双面光栅化时 Godot 自动翻转背面法线的问题，实际日照下出现严重黑褐色碎条。
世界单份草卡现在在 fragment 中仅对背面撤销这次自动翻转，保留原向上/弯曲法线。
该修正受 `GRASS_SINGLE_SIDED_GEOMETRY` 限定，不改变其他树叶和小场景原模型。

`tools/verify_grass_backface_lighting.gd` 新增实际方向光检查：微风/大风各四个观看方向，
使用真实草贴图、4× MSAA 和原 v7 双份几何作参照。旧错误最多偏离 5153 像素，
修正后最多 35 像素超过 3/255（640×480）。附加 `-- --world` 会在北部草地固定机位，
分别保存错误版本、修正版本、关闭曲线 LOD 的对照图，供人工检查。
截图与报告在 `.vegetation_art_build/grass_gust/lighting/`。不要用环境光轮廓测试替代日照验收。

新流入的分块自动绑定同一材质、时钟和几何 LOD，剔除余量为 1.8 m，原烘焙根包围盒保持。
GPU 轮廓对照覆盖旋转、非等比缩放和回弹时刻，共享曲线与原路径最多 123 像素超过
3/255 差异（640×480）；该结果是数值/画面一致性检查，不替代人工远距 LOD 观感判断。

烘焙签名应继续为 `b3f8cc2f8957e6b70ae3f4e2691ecc1debfcfcd1d9a1da524811694b43da4d31`。
未更改被签名的采样代码，没有写入烘焙文件。

## 检查与记录

### 驾驶流式加载修复（2026-10-25）

实际移动测试发现：新草块先上传完整网格，再由 `child_entered_tree` 回调切换到远距 LOD。
这会触发填充后 MultiMesh 的网格切换。Godot RD 的
[`_multimesh_set_mesh` 路径](https://github.com/godotengine/godot/blob/master/servers/rendering/renderer_rd/storage_rd/mesh_storage.cpp)
在没有 CPU 数据副本时会执行 GPU buffer readback，随后才尝试重建包围盒；已有 custom AABB
也不能跳过前面的读回。这是本轮主要阻塞来源，不是烘焙失效。

修复包含：上传前由显示回调选择目标网格；近/中距草块在首次 bulk upload 前建立 Godot 内部
CPU transform cache；远距使用无额外 CPU 副本的 MultiMesh。远→近从现有后台烘焙缓存重建
显示容器，缓存未到达时保留原粗草；64 m 内提前请求该数据。近→远从 CPU 副本重建远距容器，
释放副本，正常运行不从 GPU 读回实例。近/中距之间直接切换网格。每轮 LOD 更新另外限制
约 1 ms 的变更目标预算；单次 API 调用仍不可抢占，因此不是严格的最长帧保证。

世界坐标、密度、随机状态、材质、B 风参数和密度渐隐不变，采样/生成签名不变，无需重新烘焙。
显式 `set_optimized(false)` 是离线原版比较入口，可以同步读回，不用于正常游戏。

`tools/profile_grass_streaming_wind.gd -- --grass-profile --tag=delivery` 在 1600×900 下，
北部草地以相机模拟 18 m/s、324 m 路线，8 s 冷加载、18 s 移动、5 s 返回；不是房车物理测试。
修复前后同路线实测：

| 指标 | 修复前 | 最终版本 |
| --- | ---: | ---: |
| streamer tick 平均 / P95 | 13.98 / 18.42 ms | 1.84 / 4.76 ms |
| 草块提交平均 / P95 | 13.33 / 18.23 ms | 1.20 / 2.17 ms |
| 单次 LOD 变更最长 | 31.19 ms | 3.95 ms |
| 一轮 LOD 更新最长 | 35.57 ms | 8.21 ms |

仅上传前选好 LOD 已能去掉大多数加载回调阻塞，但已有块切换仍慢，因此补充了局部 CPU 缓存。
曾测试全常驻副本，额外占用峰值 916 MiB，未采用；最终局部副本路线观测峰值约 115 MiB，
随近/中距草块释放，不写入磁盘，不增长烘焙体积。这与原 96 MiB 解压/展开缓存是两种不同用途的缓存。

测试输出在 `.vegetation_art_build/grass_gust/streaming/`；`baseline.json` 与 `delivery.json`
分别保存本轮前后数据。中间标签为排查版本，不能当作最终结果。启动冷帧、场景复杂度和 GPU
仍会限制整体帧率；最终 streamer tick 最大约 19.6 ms，不能声称所有上传/刷新尖峰都已消除。
三出生点集成检查另验证完整烘焙签名、相同实例 buffer 在缓存/网格切换后保持一致、远处释放
副本、返回近处恢复详细网格，及所有草地菜单/交互检查。

`tools/verify_grass_gust.gd` 使用真实 GPU 检查原微风对比、根固定、世界风向、B 草尖独立形变、
无空间传播、冻结/慢放、基线/B 菜单映射、参数生效与面板展开收起。
基线保留旧节奏回归检查；B 不要求每秒大幅摆动，以持续受压的时间占比作为诊断。
自动检查通过不代表视觉验收，应以实际连续运行和用户判断为准。

`tools/verify_world_grass_wind.gd` 另在真实 1021 场景检查 B 参数、完整烘焙复用、共享草地颜色、
风力菜单及 H 隐藏、跨出生点加载的新草块、剔除边界与房车拨草。
世界报告和截图在 `.vegetation_art_build/grass_gust/world/`。
同一进程、相同场景/机位还会依次测原四段逐顶点版本与共享曲线 + 几何 LOD。
计时时暂停继续加载草块，保留人物和画面渲染；结果不能与不同机位或其他应用占用下的截图
直接比较。首次加载/移动的性能和静止视角应分别观察。

世界 1600×900、同机位各 90 帧动态风采样（原版指本次接入前的完整 v7/B 路径，非旧 v6）：

| 位置 | 原版 GPU 中位数 | 优化 GPU 中位数 | 每帧图元：原版 → 优化 |
| --- | ---: | ---: | ---: |
| 2 南部环塔主桥 | 10.05 ms | 3.59 ms | 2728 万 → 774 万 |
| 6 北部山坡草地 | 42.30 ms | 20.69 ms | 9129 万 → 2487 万 |

以上计时来自背面法线修正前的优化版本，只能作为性能历史记录，不代表当时画质通过。
这些是顺序动态采样，不是逐帧锁定相同风相位的离线 GPU 基准。优化后最密集位置仍可能超过
16.67 ms，不能保证所有位置稳定 60 fps。实际总帧时间还受分辨率、编辑器及其他应用 GPU 负载影响。
