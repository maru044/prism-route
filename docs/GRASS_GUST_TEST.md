## 当前运动

大风以持续弯折为主，偶尔短暂回弹后重新压弯。宏观风压全场同时作用，不包含麦浪前沿或
逐丛错峰。草身与草尖分开：草身承压，草尖另有小幅快速运动。

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| 持续弯折角 | 85° | 受压状态的草梢切向角，不是整株刚性旋转角 |
| 回弹最小角 | 45° | 回弹时仍保留弯曲 |
| 回弹间隔 | 4.2 s | 每段内全局事件时机略变，无空间传播 |
| 草身响应 | 0.85 Hz | 一次事件约 1.18 s；不是每秒持续大幅循环次数 |
| 草尖细摆 | 2.4 Hz / 4° | 独立于草身响应速度 |
| 梢端后随 | 0.045 s | 沿高度的延迟，不是不同草丛的延迟 |

本次将草身响应从 1.05 调至 0.85 Hz，一次事件从约 0.95 s 延长到 1.18 s，约慢四分之一。
回弹间隔、压弯角度与草尖细摆不变。四阶段仍使用首尾平滑的五次插值。
这些是美术调参，不是实测植物的物理标定。

「参数 / 画质诊断」可调整上述参数和阶段比例，冻结草风或切换 0.25 倍慢放。
少量逐丛/卡片草尖**幅度**差异是可选项，默认关闭，不改变主风压相位。
固定法线、关闭风明暗色带、纯白裁剪、不透明草卡、单张草卡可用于诊断纸片感和闪动。
它们不是正式材质设置。切换基线/B 不重置草时钟；重开场景恢复默认值。

## 检查与记录

### 驾驶流式加载修复（2026-10-25）

实际移动测试发现：新草块先上传完整网格，再由 `child_entered_tree` 回调切换到远距 LOD。
这会触发填充后 MultiMesh 的网格切换。Godot RD 的
[`_multimesh_set_mesh` 路径](https://github.com/godotengine/godot/blob/master/servers/rendering/renderer_rd/storage_rd/mesh_storage.cpp)
在没有 CPU 数据副本时会执行 GPU buffer readback，随后才尝试重建包围盒；已有 custom AABB
也不能跳过前面的读回。这是本轮主要阻塞来源，不是烘焙失效。

修复包含：上传前由显示回调选择目标网格；近/中距草块在首次 bulk upload 前建立 Godot 内部
CPU transform cache；远距使用无额外 CPU 副本的 MultiMesh。远→近从现有后台烘焙缓存重建
显示容器，缓存未到达时保留原粗草；64 m 内提前请求该数据。近→远从 CPU 副本重建远距容器，
释放副本，正常运行不从 GPU 读回实例。近/中距之间直接切换网格。每轮 LOD 更新另外限制
约 1 ms 的变更目标预算；单次 API 调用仍不可抢占，因此不是严格的最长帧保证。

世界坐标、密度、随机状态、材质、B 风参数和密度渐隐不变，采样/生成签名不变，无需重新烘焙。
显式 `set_optimized(false)` 是离线原版比较入口，可以同步读回，不用于正常游戏。

`tools/profile_grass_streaming_wind.gd -- --grass-profile --tag=delivery` 在 1600×900 下，
北部草地以相机模拟 18 m/s、324 m 路线，8 s 冷加载、18 s 移动、5 s 返回；不是房车物理测试。
修复前后同路线实测：

| 指标 | 修复前 | 最终版本 |
| --- | ---: | ---: |
| streamer tick 平均 / P95 | 13.98 / 18.42 ms | 1.84 / 4.76 ms |
| 草块提交平均 / P95 | 13.33 / 18.23 ms | 1.20 / 2.17 ms |
| 单次 LOD 变更最长 | 31.19 ms | 3.95 ms |
| 一轮 LOD 更新最长 | 35.57 ms | 8.21 ms |

仅上传前选好 LOD 已能去掉大多数加载回调阻塞，但已有块切换仍慢，因此补充了局部 CPU 缓存。
曾测试全常驻副本，额外占用峰值 916 MiB，未采用；最终局部副本路线观测峰值约 115 MiB，
随近/中距草块释放，不写入磁盘，不增长烘焙体积。这与原 96 MiB 解压/展开缓存是两种不同用途的缓存。

测试输出在 `.vegetation_art_build/grass_gust/streaming/`；`baseline.json` 与 `delivery.json`
分别保存本轮前后数据。中间标签为排查版本，不能当作最终结果。启动冷帧、场景复杂度和 GPU
仍会限制整体帧率；最终 streamer tick 最大约 19.6 ms，不能声称所有上传/刷新尖峰都已消除。
三出生点集成检查另验证完整烘焙签名、相同实例 buffer 在缓存/网格切换后保持一致、远处释放
副本、返回近处恢复详细网格，及所有草地菜单/交互检查。

`tools/verify_grass_gust.gd` 使用真实 GPU 检查原微风对比、根固定、世界风向、B 草尖独立形变、

基线保留旧节奏回归检查；B 不要求每秒大幅摆动，以持续受压的时间占比作为诊断。
