# 1021 碰撞容错

2026-10-22：保留完整地图碰撞网格和已接入的渲染LOD，通过移动控制与碰撞层处理细小障碍。未修改CAD或GLB，也未生成独立碰撞代理。

## 已确认的原因

地图中有9件独立路面标线，位于岸路、沙嘴道路、出口小桥。实际Jolt射线测得标线高于道路约22～27 mm；先前它们和墙体一样位于人物/车辆使用的实体碰撞层。房车还是以较长的直立盒体移动，原控制器没有辅助越坎；独立测试中，10 cm直角小坎可以让房车一直停在前方。

接触恢复容差 `safe_margin` 的作用不是忽略所有小物件或填补所有缝隙，因此没有靠全局降低物理精度解决。

## 修改

- 1021人物的接触恢复余量为4 mm，额外越坎高度上限10 cm；房车为6 mm与12 cm。仍保留原有贴地长度、坡度限制、车身碰撞盒和车辆速度。
- `surface_motion.gd` 先执行正常移动，仅在接地、非上升、水平移动被边缘阻挡时重试。依次用完整身体形状向上、向前、向下扫掠，要求顶部净空、路径可通过、落脚面坡度可行走，并限制高度变化。同高度落脚也可绕过虚假的接缝边缘接触。
- 不在空中启动越坎；无落脚面时不接受移动。明显墙体、低顶障碍和实际断崖保留其物理效果。
- 标线继续保留显示和旧采样碰撞层，但不加入人物/车辆使用的新实体层（位6，值32）。其他非水面的实体继续阻挡人物和车辆，包含护栏与墙体。
- 人物、房车、出生点净空查询、换车净空查询和轮胎贴地查询使用一致的实体层。不会让轮胎跟随凸起的标线。
- 共享控制器的额外越坎默认值仍为0；只有1021场景主动启用该配置。其他场景保持原行为。

Jolt当前已默认开启移动查询和模拟的 enhanced internal edge removal，本次保留设置。它不能消除两个独立物理体之间的所有接缝问题，因而仍需要上述移动容错。

## 验证

`collision_tolerance_fixture.json` 使用实际人物/房车控制器和碰撞形状，以固定60 Hz物理步长运行：

- 人物通过8 cm小台阶，房车通过10 cm小台阶；房车旧逻辑在同一10 cm小坎处被卡住，启用后通过，记录一次辅助越坎。
- 3 cm交错高差、4 cm拼缝及12 cm窄缝可通过。
- 70 cm高障碍继续阻挡，顶空不足时不能抬升穿过顶板。
- 无支承断崖正常坠落，没有自动跨空。
- 房车18 m/s通过10 cm台阶，同时在18 m/s正面撞向70 cm高障碍时仍被阻挡。

`collision_tolerance_layers.json` 在实际地图中逐一检测9组标线：旧采样射线仍命中标线，人物/车辆射线命中其下道路；其余物体的实体碰撞保留，旧种植查询层逐件保持。

完整场景继续运行 `verify_map_1021.gd`，核对8个出生点的人物行走、C切换、房车驾驶、轮胎接地及固定树木布局。原始结果为 `assets/world/current_map_validation/review/validation.json`。

## 草地数据

不需要重新烘焙：本轮没有改变GLB和草根采样所使用的旧碰撞层。实际校验原11,321格烘焙可正常打开，签名仍为 `71d4242bd86b32270ec0d7234ae412701bdd23be22c6799c02989dd495e48a88`。

这套容错不修复大幅错位的道路、大洞或缺失桥面；这些仍需修复模型。物理标志牌、护栏和墙体也不会因为体积小就被统一排除，当前明确排除的是独立的路面标线。

工具：`tools/verify_collision_tolerance_1021.gd`、`tools/verify_collision_layers_1021.gd`。报告均在当前地图的 `review/` 目录。

官方机制：[CharacterBody3D接触容差](https://docs.godotengine.org/en/stable/classes/class_characterbody3d.html)、[Jolt碰撞边缘处理及限制](https://docs.godotengine.org/en/stable/tutorials/physics/using_jolt_physics.html)。
