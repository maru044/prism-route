# 建筑曲面的支撑与衔接：建模方法记录

更新：2026-10-15。适用于 Prism Route 当前的暖白建筑、曲面地形与道路设计。

## 设计依据与适用范围

后续建模以对应区域的效果图、空间用途和场地约束为依据。连续、展开的底部结构是当前需要保留的设计语言；具体的支脚数量、分叉关系、层间连接和建模方法随区域变化。

本次 [v03 样段](concepts/cliff_terraces_2026-10-15/support_cell_v03/README.md) 验证的是**两根各自独立的单支脚，向上展开并共同融入一片顶面**。它没有真正的柱身分叉，也没有多层桥面、交错壳体或复杂洞室。用户认可继续记录这一做法，同时明确它不能成为所有构件的统一模板。

## 建模前先理解底部空间

先从效果图辨认支脚在哪里落地、向哪个方向倾斜、肩部如何展开，以及展开后形成哪些可进入的空隙。再区分顶面、侧缘、腹部和支承之间哪些地方需要连续，哪些地方是有意的分层、接缝或独立构件。

重点看轮廓和截面：脚部到肩部的宽厚变化、桥底的拱高、悬挑方向、开口两侧的不对称、以及纵向起伏和横向弯曲如何组合。可行走顶面可以局部平缓；仍需设计底部体量和展开过渡。单纯让一张带状顶面起伏，再封侧面、把底面局部拉低，容易重复前一版的板片感。

场地约束同时进入设计：主要修改区域在标注弧线的陆侧；整体高度沿用当前草稿约束。中层道路使用实际三维路面和路线核对，不能用 Z=0 的示意中线代替。需要退让空间时，中央窄连接可作为艺术化桥身一起设计。

## v03 单支脚展开方法

脚本：[rhino_continuous_support_cell_v03.py](../tools/rhino_continuous_support_cell_v03.py)。这次在 Rhino 中通过 Python 构建控制网，再生成原生、可编辑的 SubD。

1. **建立顶面与有厚度变化的腹部。** 顶面具有纵向起伏和横向曲率；腹部在支承肩部附近增厚，在跨中逐渐减薄。厚度和支脚位置共同决定拱腹，不能只由统一偏移量决定。
2. **在腹部拓扑中预留支承根部。** 删除两个局部面区，各自保留一圈边界顶点。这些顶点直接作为支柱最上方截面，与腹部共享，不另造一根柱子贴上去。
3. **从肩部向脚部逐段组织截面。** 截面逐渐收束，中心偏移形成倾斜，截面方向逐渐旋转，轮廓向圆滑脚部过渡。相邻环连接成四边形面，形成同一连续表面。
4. **让外缘滚转进入腹部。** 外缘通过多圈截面衔接顶面和底面，控制圆转和厚薄变化，避免只用直立封边表达整个侧缘。
5. **收好脚部，检查细分后的实际形体。** 本次脚底封口放到基准地面以下，作为样段收口处理；后续应按真实落地地形重新确定脚底位置和接合关系，不能统一套用 -4 米。
6. **转换为平滑 SubD，并从桥下审视。** 先检查支脚、肩部、拱腹的轮廓和过渡，再看上方整体。增加细分密度只改善显示，不能替代形体设计。

本次控制网为 1,246 个顶点、1,272 个面；单元闭合且只有一个连通体。尺寸、环数、约 28 度扭转、两根支脚的位置和肩部宽度均为该样段的具体参数，不是风格规则。

## 不同效果图需要不同构造

区域分布遵循用户最新要求：**地形底层主要保持实体，支撑只用于局部需要镂空、穿越或开敞的区域**。两端及普通落地段采用实心底层，不能因为单支脚样段有效就沿整圈重复镂空。开敞位置首先围绕实际隧道入口组织；同时退让遮住支承的前排地形，让肩部、拱腹和支脚从外侧可见，并留出适当的侧向穿透。支撑不能被实心底层包在里面，也不能在没有空间用途的位置单独开廊。

当前应用记录见 [v05 两处隧道入口外露支撑](concepts/cliff_terraces_2026-10-15/exposed_portals_v05/README.md)。[v04](concepts/cliff_terraces_2026-10-15/hybrid_solid_v04/README.md) 为历史版本，其偏离入口的支撑廊位置已被用户否定，在 v05 中恢复为实体。

以下为选择建模方式的思路。目前已验证单支脚展开，并在 v05 中应用于两处入口，按实际道路拱形预留体调整腹部；真正分叉、多层交汇与复杂洞室尚未实现或验证。

| 效果图中的关系 | 建模重点 | 与 v03 的区别 |
| --- | --- | --- |
| 单支脚向宽顶面展开 | 共享根部边界、截面收束、偏转、肩部与腹部过渡 | 可以沿用本次局部方法，再调整截面和比例 |
| 柱身真正分叉，承接多个方向 | 先组织分叉节点、各分支截面及分支间的空隙，再处理连续表面 | 单圈截面收束只能形成一个柱身；增加柱子或复制根部不能替代分叉节点 |
| 多层桥面或壳体交汇 | 明确各层标高、连接顺序、穿行空间，以及接触或分离关系 | 需要围绕交汇节点重新组织拓扑；不能把若干单元重叠后就认为完成衔接 |
| 大跨度连续拱腹或拱洞 | 从落地到跨中的完整截面变化、两侧厚度、入口与内部体量 | 拱腹本身是主要形体，不能只在薄侧壁上切一个孔 |
| 不对称悬挑、扭转翼面 | 悬挑方向、肩部受力感、截面转向及与后方体块的接合 | 不能简单镜像或均匀重复支脚；是否需要独立翼面按参考决定 |
| 实体建筑、洞室或分层露台 | 外部形体与内部空间、层板、开口深度、墙体及可进入路径 | 连续外表面不代表内部结构已设计；可保留符合参考的独立构件与接缝 |

根据形体可选择 SubD、NURBS 曲面分片与过渡，或其他网格建模方法。Python 可用于组织控制网和截面；Rhino 或 Blender 的选择由编辑、衔接和导出需求决定，不固定使用一种实现。

## 验证顺序与判断边界

先用侧面、低视角和桥下视图验证造型，再检查整体背景关系。隔离视图用于辨认支柱自身的体量，不能替代带地形和道路的场景视图；草稿地形遮挡不能成为忽略曲面本身问题的理由。

几何检查包括有效性、闭合、流形、连通体数量、法线、高度和接合边界。一个闭合、连通的模型仍可能有不理想的曲率、局部自交或错误的空间关系。使用 SubD 不代表所有节点都达到全域 G2 连续；需要特定连续性时，要针对相应过渡检查。

道路检查需包含路面宽度、坡度、支脚占地和上方净空。v03 的道路射线没有命中新样段，因此只记录“本次抽样无命中”，没有新的隧道净空数值，也没有完成游戏内通行验收。

确认局部形体后，才依据整张效果图扩展支承体系，处理新旧地形接缝、种植顶面和道路。视觉造型验证与结构计算、完整自交检查、游戏网格及碰撞验收分别记录。

目前种植设计暂缓，新增曲面的顶面统一显示暖白建筑材质。未经设计的植物覆盖带先隐藏保留；后续按活动空间、可达性、土层及参考图安排种植范围，避免死板地把每个顶面套成建筑边框和绿色中心。

## 版本保留与复用

保留旧方案和修改前的完整 3dm 快照。新局部结构使用独立图层和独立样段文件，原始地形的修改范围、隐藏状态和场景副本另行记录。不要直接覆盖唯一的源模型。

v03 的会话调用及文件位置见 [样段记录](concepts/cliff_terraces_2026-10-15/support_cell_v03/README.md)。当前脚本依赖该 Rhino 会话的场地状态；重新打开文件后，状态恢复尚未自动化，不能直接重复发布。

复用时先确认参考需要哪一种构造，再选择可复用的截面、过渡或控制网方法。复用的是建模思路，不要求所有构件都做成相同的单柱展开形体。
