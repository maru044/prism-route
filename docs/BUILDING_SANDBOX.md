# 建筑构件与家园基础验证

日期：2026-11-11。需求来源：[Issue #25](https://github.com/maru044/prism-route/issues/25)。当前交付为正式地图内的最小建造验证，不代表角色入住、自动导航和完整生活模拟已经接通。

## 入口与操作

从 `scenes/main.tscn` 启动，在地点菜单选择 **建造地块 · 青蓝平台**。这里已有一栋两层示例屋；**建造地块 · 北侧低地** 是第二块空场地。

- 点击“建筑构件 · F7”或按 F7 进入／退出建造模式；Esc 退出。
- 选择地块、组件和楼层，左键确认放置，R 切换方向；门墙的四个方向包含反向开启。
- WASD 平移视角、右键拖动旋转、滚轮前后移动。
- Delete 拆除鼠标指向的构件；Ctrl+Z／Ctrl+Y 撤销／重做。
- 建造模式 E 开关指向的门；行走模式靠近门后按 E 开关最近的门。
- “走到入口”退出建造并将玩家放在当前地块入口；“保存／读取”操作独立家园存档。

默认存档为 `user://construction/home_v1.json`。首次没有存档时生成示例屋，之后读取玩家布局；存档带版本、组件规格指纹、稳定组件与房间ID。无效存档拒绝读取并保留现场与原文件，也禁止继续覆盖保存；读取兼容的有效存档后恢复保存。验证器使用忽略目录中的隔离存档，不读取或覆盖玩家家园存档。

## 已有组件与尺寸

`assets/construction/basic_kit/kit.glb` 是一个共享网格库，`catalog.json` 保存规格、碰撞、功能与真实地块坐标。组件按目录实例化，不为每块墙另写文件。

| 构件 | 规格／用途 |
| --- | --- |
| 地板／楼板 | 2×2m，厚0.2m；局部原点为格子的角，顶面Y=0 |
| 墙 | 宽2m、厚0.18m、净高3.4m；沿局部X轴，Z=0为边界中心 |
| 门墙／开放门洞 | 门洞1.4×2.4m，门扇可开关并有真实碰撞 |
| 窗墙 | 真实窗洞、木框、轻透明玻璃，整面碰撞阻止穿窗 |
| 平屋顶 | 2×2m，位于对应楼层上方3.6m；楼板已覆盖时拒绝重复屋顶 |
| 楼梯 | 2×6m，升高3.6m，24级可见踏步；独立凸体斜坡碰撞 |
| 入口缓坡 | 2×2m，升高0.2m；可见楔形与碰撞一致 |
| 栏杆 | 宽2m、高约1.1m，平台及楼梯井防护 |

地块基准为真实地面0m／35m；首层完成面加0.2m，层距3.6m、净高3.4m。顶层屋顶完成面在首层基准上方7.4m。当前验证两层，不能用2m平面模数推断层高。

复用现有 `prism_geo_bed`、`prism_geo_chair`、`prism_geo_desk` 场景，保持床面0.46m、座面0.42m、桌面0.838m与既有动作锚点；目录增加占地、用途标签和经过现场胶囊净空检查的 `Anchor_Front`。椅子的验证包装补充简化支撑与靠背碰撞，床／桌沿用原碰撞并接入33层（原第1层＋正式角色第6层）。床先按一个睡眠槽位预留，不将中心／床边／床头动作参考当作三个床位。

家具状态仍为 **anchors_ready**：已经检查锚点和静态入口净空，没有执行角色睡觉／坐下的完整动作适配与进出流程。没有增加 NPC 寻路或入住系统。

## 数据和运行时接入

- `scripts/construction/building_data.gd`：整数格子与规范边界键、放置和拆除依赖、家具轮廓、撤销重做、按层四方向空间检测、覆盖检查、稳定房间编号。家具保留实际米制坐标，辅助吸附0.5m。
- `scripts/construction/basic_kit.gd`：复用导入网格和材质，恢复简单盒体／凸坡碰撞、家具锚点、门扇枢轴。墙／门／窗／栏杆共享边界槽位，替换而非重叠。
- `scripts/construction/construction_world.gd`：两个地块、示例布局、编辑面板、场景增量同步、动态草遮罩和独立存档。
- `scripts/map_1021.gd`：正式世界装配、地点菜单、输入隔离及草材质绑定。

示例屋14×10m底层、8×8m二层房间及露台，共164个建筑／家具实例。空间分析输出五个区域，能展示室内、露天和开放空间；床／桌提供初步 bedroom／work 用途，不代表 Issue 中的完整走廊识别或家具加权分类已经完成。门状态不改变房间ID，开放门洞在空间图上传递室外暴露，有地板的露台不能据此认定室内。拆分／合并按确定性的单元重叠匹配旧ID；摆家具和门开关不改空间身份。

二层楼板同时提供下层顶部覆盖；同高度再放屋顶会拒绝。楼梯需要完整下层支撑、上层落脚点与开口，不能将楼板放回楼梯井；示例井口两侧及底端有栏杆。拆除会检查上层楼板、墙体、屋顶、家具等直接依赖。这里只做基础依赖约束，尚无结构受力／悬挑计算。

## 植被：指定地块禁树，草地动态覆盖

两块60×60m地界按各自旋转后的局部坐标判断，并限制实际支撑高度。用户指定地块需要清树，因此此处是**明确的地块禁树规则**，在 `world_editor.gd` 中优先于手工树显示；其他区域依然保持“手工编辑优先于自动排除”。验证时每块各29条树记录被排除。原始树位、手工编辑文件和存档不删除不重写，地界外密度不变。

每块地用一张256×256 R8运行时草遮罩，双地块原始像素合计128KiB。确认放置、拆除、撤销或读取时，从当前贴地地板与入口坡道的覆盖并集重建遮罩，并向外留0.35m余量。二层楼板、屋顶及预览幽灵不增加压草范围。并集重建避免重叠覆盖拆除后错误恢复。

`shaders/environment/construction_grass.gdshaderinc` 与正式草风shader共用草根世界坐标、地块逆变换及±0.65m高度窗口；范围外立即返回。近／中／远草均使用同一正式材质。压草只改变显示，保留已烘焙的原始根与随机状态，以便拆除后恢复；没有改采样函数、生成签名或全图草包。

遮罩裁掉的草仍有顶点阶段计算，不能称为零成本或实际根点已删除。当前仅两块小地块，先保留可逆遮罩；未来若大片铺满，再从缓存按覆盖过滤显示实例，不在每次放置时重烘焙全图。

## 制作与验证

作者脚本 `tools/build_basic_construction_1111.py` 在 Rhino 内存中生成米制局部几何，并读取“沙盒范围”的两条真实闭合方框。它不向地图加对象、不保存地图、不创建完整或组件 `.3dm` 备份。

1. Rhino 执行作者脚本的 `export_source()`，写入 `.current_map_build/construction_1111/source.json`。
2. 项目根运行 `python tools/build_basic_construction_1111.py --package`，生成单一网格库和目录。
3. Godot重新导入网格库后运行同一个验证器：

```powershell
$godot = '.current_map_build/runtime/Godot_v4.7.2-stable_win64_console.exe'
& $godot --headless --path . --script res://tools/verify_construction_1111.gd -- --logic-only
& $godot --path . --script res://tools/verify_construction_1111.gd
```

验证复用正式 `main.tscn`，不新增平行地图。结果、隔离存档和覆盖更新的截图集中在 `.current_map_build/construction_1111/`。纯数据检查包含重复放置、越界、跨墙家具、楼梯开口、重叠楼板／屋顶、撤销重做、门状态与房间身份、拆墙合并、拱门外泄及900单元分析。正式场景检查真实角色碰撞、家具锚点与入口、两层地板、存档回读、输入隔离、树木排除、动态草遮罩及受保护文件哈希。

最终306项检查通过。实际角色通过入口、开门后的走廊、上楼及下楼四条路线，完成高度误差约3.5mm；关门时正确阻挡。900单元一次完整空间分析约6.9ms，属于该次运行观测，不是全场景性能承诺。已人工查看总览、室内、楼梯及同一机位的 `grass_before.png`／`grass_floor.png`／`grass_restored.png`：地板下压草并在拆除后恢复。受保护的全局树位、手工编辑文件、全局草清单和小镇根包前后哈希一致。

### 房间ID专项复查（2026-11-11）

用户追问后，原验证器增加 `--room-ids-only` 模式，直接运行生产 `BuildingData` 的隔离逻辑回归。57项检查通过，结果追加原 `verification.json` 的 `room_id_followup`，不覆盖此前306项正式场景结果，也不写玩家存档。本次没有修改房间ID算法。

- 添加、移动、移除床只改变用途，空间ID不变；拆屋顶与撤销只改变覆盖状态，ID保留。
- 连续开／关门保持两侧ID。新分隔墙拆分时，最大重叠子区域继承原ID，另一侧获得新ID，检查无重复。
- 拆墙合并保留最大前身ID；再拆分时小区域分配全新ID，不复活已退役的小房间编号。
- 新增独立空间、撤销，以及JSON回读后重新分析，逐格检查原有房间归属ID保持；不同地块采用各自命名空间。

隔离用例的具体结果为：原房间 `identity_room_0001` 拆出 `identity_room_0002`，合并保留0001，再次拆分生成0003。当前示例屋实际ID为 `coastal_room_0001`～`0005`，含室内及开放／露天空间，不能把五个ID说成五个有效室内卧室。角色入住尚未接通，因此房间合并／拆分后的NPC床位引用迁移仍是后续入住阶段的工作。

接入新节点时暴露了原椭圆中庭入口的同高命中顺序问题：入口平台与宿主顶面共面，第一条射线可能命中宿主，原代码便拒绝其指定平台来源。`resolve_spawn()` 现在仅在要求来源不匹配时，在原命中高度±2cm内逐个排除重叠碰撞体查找指定来源；不搜索其他楼层、不放宽来源约束。最终包含新增地块在内的24个原有／新增入口全部解析通过。

存档数字按JSON规范读取为浮点数，数值等价性与稳定ID是验收依据，不能将字符串中 `1`／`1.0` 的格式差别判为布局变化。

导出资源列表已包含构件库、运行脚本和既有家具场景，`catalog.json` 加入非资源文件包含规则，原导出配置工具也保留该规则。本轮验证编辑器运行，未生成新的可执行发布包。
