# Prism Route

近未来废墟与自然复苏主题的 Godot 3D 项目。当前已搭建可探索的大世界、角色与房车控制、植被编辑和流加载，并建立 Rhino 建筑同步、VRM 角色入库及共享 MMD 动作的制作流程。

**当前状态：2026-11-10。** 本 README 提供现用入口和制作导航；详细验收数据保留在对应文档中。

## 启动项目

使用 **Godot 4.7.2、Forward+**。当前 Windows 配置使用 D3D12、Jolt Physics，默认窗口 1920×1080、帧率上限 60 FPS。

1. 首次克隆后执行 `git lfs install` 和 `git lfs pull`，下载完整地图及角色大文件。
2. 在 Godot 中导入本目录的 `project.godot`，等待资源导入完成。
3. 按 **F5** 打开标题界面；独立检查场景在打开后按 **F6**。

**F5 打开标题界面。** 选择「开始游戏」后进入 `scenes/main.tscn`，它实例化正式地图 `scenes/map_1021.tscn`。默认出生点为「南部 · 初始洞穴」。[标题界面制作指南](docs/TITLE_SCREEN.md)

| 场景 | 用途 |
| --- | --- |
| `scenes/ui/title_screen.tscn` | F5 标题界面 |
| `scenes/main.tscn` | 正式世界，可单独运行以验证地图 |
| `scenes/character_roster_review.tscn` | 累计角色入库检查：待机、步行、跑步和衣发物理 |
| `scenes/character_mmd_vrm_validation.tscn` | 已选 MMD 动作库、多人同步及共享模型替换验证 |
| `scenes/character_motion_test.tscn` | 独立 CC0 动作候选预览与筛选 |

角色检查也可运行 `tools/run_character_roster_review.ps1`，共享动作检查可运行 `tools/run_mmd_vrm_validation.ps1`。脚本支持 `-GodotPath`；默认本地运行时位于不入库的 `.current_map_build/runtime/`，新机器需要自行指定 Godot 路径。

## 游戏内 LLM 客户端

- 和初始神殿的花火交谈时，底部「自由对话」使用对话模型和流式回复。这个入口的请求只包含文本消息和生成参数。
- 游戏内按 Esc，在「帮助」页打开「游戏助手」来使用辅助模型。它可以查询游戏状态和有效定位点。移动到定位点前，由玩家确认传送。
- 在标题界面「API 配置」里分别填写自由对话和游戏助手的 API 地址与密钥。点击「获取模型」从对应的 `/models` 选择模型 ID，也可手动输入服务商提供的 ID。点击「保存」会将当前入口的地址、模型 ID 和密钥写入本机 `user://llm_client.cfg`。两个入口的历史和草稿随世界进度写入游戏存档，重启后可从标题页恢复。
- 发送后同一按钮会变成「停止」。倒回会移除最近一轮并把原文放回输入框。自由对话还可以重新生成、切换版本和续写。助手可以重新生成只读查询和待确认提议，已执行传送的回合不能重新生成。

入口固定决定模型。自由对话使用对话配置，发送文本消息和生成参数。游戏助手负责普通问答和游戏操作，整轮工具循环沿用发送时的辅助模型、地址和密钥，最多执行三轮工具调用。两个入口各自保存会话，切换时结束当前请求。配置缺失或请求失败会在当前入口报错。

自由对话自动加载 [世界书目录](assets/ai/worldbook) 的 Markdown。每份文件以 `{"depth": 4, "name": "世界规则"}` 这样的 JSON 文件头起始，下一行用 `---` 与正文分隔。原始 Reborn 导出留在项目外。

`depth` 是唯一的排序字段。深度从裁剪后的聊天末尾倒数消息，超过聊天长度时放在历史开头，同一深度的正文合在一个 Markdown 里。当前从深到浅为《破限》999、《角色信息与世界观》980、《玩家人设》978、《核心设定集》975、《角色与场景》900、《世界规则》4、《输出格式》0。Miku 的完整人设在《角色信息与世界观》中。世界规则插在最后四条聊天消息之前，本轮玩家输入计入其中。《输出格式》紧接聊天历史，末尾是 Reborn 的「防截断」段，所有自由对话模型共用。

《角色与场景》提供游戏当前对话对象 `{{npc_name}}` 和当前地点 `{{dialogue_location}}`。初始神殿入口传入「花火」和「初始神殿」。新增游戏标签时，以实际由游戏提供的数据为准。预留或停用文件放在 `assets/ai/reference`。文件头错误和重复深度会在游戏内显示出错文件。

玩家可直接编辑 [《玩家人设.md》](assets/ai/worldbook/玩家人设.md) 的正文，填写称呼、身份和背景。Windows 导出版首次打开自由对话时，将默认人设复制到 `%APPDATA%/Godot/app_userdata/Prism Route/玩家人设.md`。客户端优先读取该本地文件，重新打开自由对话即可加载编辑后的内容。请保留文件头和 `---` 分隔行。清空正文即可停用玩家人设。

游戏版提示词已移除插图要求，文风规则集中在《世界规则》。两个入口都按约 100 万 token 的上下文预算在本地粗估。预算包含提示词、当前输入、对话历史、助手工具消息和输出余量。需要裁剪时按完整回合从最早记录移除，聊天栏保留本地历史并提示本次省略了几轮。世界书的插入深度按实际保留的聊天消息计算。模型的实际上下文上限取决于服务端。

助手查询会返回角色名、最近地标和传送受限原因。每轮接受第一个有效传送提议。后续问答期间仍可看到该提议，发送中暂不可确认。确认失败保留提议并显示原因，成功后消耗提议。新的有效提议可以替代旧提议。

助手单独加载 [助手职责](assets/ai/assistant/助手职责.md)和[工具使用](assets/ai/assistant/工具使用.md)。两份 Markdown 的文件头均标注 `"agent": "assistant"`，运行时按实际注册的工具名称选入对应说明。旧客户端专用的工具手册留在 [参考目录](assets/ai/reference/系统工具调用手册.md)。Windows 导出配置包含助手和世界书两个目录。实际凭据在标题界面的「API 配置」填写。

旧客户端的「开篇伪装对话」和「末尾格式要求」已从迁移副本移除，避免与 Reborn 的开场和输出格式叠加。Reborn 的普通请求 `assistant_prefill` 为空，`continue_prefill` 是酒馆的续写专用选项。游戏的「续写」用上一条实际回复和一条续写指令。世界书目录中的旧工具调用手册仅供参考，自由对话的请求不读取它。

自由对话装配时将相邻的同角色消息以空行合并，只改发给模型的副本。玩家原文、倒回和回复版本仍按原来的回合记录。

游戏客户端不运行 SPreset 插件，也不导入或执行它的输出预处理正则。Godot 原生处理 SSE、字面 Unicode 解码及下文列出的正文和报告标签。任意附加标签、正则替换及酒馆的展示规则不在这个处理范围内。

自由对话在 JSON 解包后还会解码回复正文中的字面 Unicode 转义，支持四位形式、花括号形式和 UTF‑16 代理对。流式片段末尾的不完整转义等待下一片，结束或停止后仍不完整的部分按原文显示。

自由对话默认显示正文，去掉 `<game>` 边界，兼容普通文本。回复中显式返回的 `<report_nya~>` 或 `<think_nya~>` 内容保存在对应回复版本里，点「查看报告」展开。后续请求只带玩家原文和已选回复的正文，连同续写在内。供应商单独返回的推理字段不进入对话栏。

### 流式回复排障

先看对话栏底部的状态。自由对话只通过「重新生成」手动重试。生成中「发送」会变成「停止」，点击后关闭本地连接并保留已收到的内容。生成期间可以写草稿，Ctrl+Enter 暂停生效。重新打开面板仍可看到失败或停止的状态。发送新问题时会提示有多少未完成回合未纳入上下文。续写失败会标记该片段，已经成功的正文仍可进入下一轮。失败后可点「复制诊断」，其中包含入口、模型 ID、失败阶段、错误摘要，以及可用的 HTTP 状态、请求 ID 和建议等待时间。复制内容采用客户端生成的摘要和已识别的常见错误短语，省略服务端原始详情、对话、完整接口地址和密钥。

游戏助手在工具尚未执行时，对暂时性网络故障、408、速率限制和常见暂时性 5xx 自动重试至多两次。默认等 1 秒、2 秒。秒数形式的 `Retry-After` 最多自动等待 10 秒。更久的等待或以日期指定的等待交由玩家决定。退避期间也可点「停止」。查询已执行而助手未返回正文时会显示查询状态。已通过校验的传送提议在生成总结失败后仍可由玩家确认。

| 状态 | 检查 |
| --- | --- |
| 域名解析失败、HTTPS 握手失败、连接超时 | 检查接口地址、DNS、证书和系统时间。建立连接的等待上限为 30 秒。 |
| HTTP 400 / 422、413 | 核对模型 ID 和接口兼容性。若提示上下文或请求过长，缩短输入，或减少历史和提示词。 |
| HTTP 401 / 403、404 | 分别核对密钥与模型权限、接口路径与模型 ID。「API 基础地址」可以直接粘贴酒馆的自定义 OpenAI 端点。服务商要求 `/v1` 时，请把它填入地址。 |
| HTTP 402 / 429、5xx | 余额或额度不足时检查账户。限流或 503 提供 `Retry-After` 时，按建议等待再重新生成。其他 5xx 可稍后重试。 |
| HTTP 错误附带详情 | 客户端最多读取 8 KiB 错误正文与 2 秒，支持 JSON 消息和 FastAPI 的 `detail`，隐藏当前密钥、常见凭据格式及 URL，最多显示 240 个字符。 |
| 返回网页或普通 JSON | 检查请求是否到达支持流式 Chat Completions 的接口，代理是否正确转发 SSE。 |
| 等待 HTTP 响应或第一段正文超时 | HTTP 响应未到时先查服务可达性。已收到响应但迟迟没有正文时，检查模型首段延迟和反代是否缓冲。每阶段最多等待 120 秒，心跳不延长正文倒计时。 |
| 流式中途停顿或断开 | 检查代理空闲超时或连接中断。客户端保留已收到的文字，可手动重新生成。 |
| 流式结束异常 | `[DONE]` 或明确的 `finish_reason` 可结束请求。收到结束原因后最多再等 2 秒。两者都缺失时，连接关闭会提示中断。 |
| 自由对话只有报告或正文为空，或助手的工具调用格式错误 | 可以重新生成。报告仍可展开查看。模型返回 `<game>` 时，显示和历史只使用标签内的正文。模型省略该标签时正常显示纯文本。 |

用下面的命令运行本机流式回归。它只连接 `127.0.0.1`，使用固定响应，无需 API 密钥。

```powershell
godot --headless --path . --script res://tools/verify_llm_stream.gd
```

## 角色与共享动作

### 角色入库

当前累计 **47 个可选角色**：原有刻晴、甘雨、胡桃、花火，加 `assets/characters/roster/catalog.json` 中的 **43 个新增角色**。新增角色使用 PMX → VRM → Godot 流程，按配置移除武器与独立道具；大部分目标角色已入库，剩余主角个别模型暂缓制作。

角色检查继续沿用同一个 `character_roster_review.tscn`，支持模型和动作切换、时间轴、速度、头发／服饰物理开关，并可进入共享动作验证场景。正式地图当前控制的仍是甘雨；入库清单用于角色资源管理与预览。

基础动作统一引用正式甘雨的 **A01 待机、A05 步行、A06 跑步**。骨盆侧移抵消、回绕重置物理及 A06 循环接缝已有专项修复。早期批次文档中的「14 个角色」「跑步仅诊断」是历史阶段状态；当前数量以累计清单为准，专项报告的验收范围以其记录为准。

制作入口：[角色批量导入指南](docs/CHARACTER_BATCH_IMPORT_GUIDE.md)、[共享移动动作修复与验收](docs/character_locomotion_1104/README.md)。每个角色／服装需要一次骨架、材质与衣发配置检查，之后跨动作复用自己的物理配置。

### 已选 MMD 动作库

当前已导入 **20 组、40 条角色位轨道**并通过全量验证。character_mmd_vrm_validation.tscn 支持第一人称（竿役视角，带防穿模眼部偏置与鼠标注视微调），并配套定制发光低台平台床 prism_geo_bed、折纸办公桌 prism_geo_desk 以及通用互动小条凳规范（[长方体条凳规范](docs/GENERIC_BENCH_INTERACTION_SPEC.md)）。身体动画资源合计约 **94.7 MiB**，不含角色、报告与可再生缓存。

先通过独立 Blender 源动作选片器筛选，再烘焙为共享人形资源。每条来源轨道保存一份身体动作，由目标 VRM 按自身骨架应用；多人组使用共同坐标和时间轴。头发与服饰在目标角色实例上实时模拟。

`character_mmd_vrm_validation.tscn` 的已选列表每组只列一次，提供搜索、人数筛选、整组／单角色查看、模型替换、时间轴与物理开关；当前预览台还支持实时曝光调节。已入库模型不等于全部模型与全部动作组合均已完成接触美术验收；体型接触、道具、表情和个别循环仍按实际使用场景调整。

| 制作步骤 | 指南 |

## 本地重建与资源管理

地图 GLB 和新增角色 VRM 使用 Git LFS。`.godot/`、`.current_map_build/` 及全图基础草烘焙是本地缓存，不随普通克隆提供。缺少草缓存时运行时会回退生成；需要完整预烘焙体验时，按 [草流加载与烘焙说明](docs/GRASS_STREAMING_ISSUE13.md) 重建：

```powershell
& tools/build_grass_1021.ps1 -GodotPath '你的 Godot 控制台程序完整路径'
```

GLB 或纹理被制作工具重写后，先在编辑器完成重新导入，再做画面验收。命令行也可执行：

```powershell
& '你的 Godot 控制台程序完整路径' --headless --editor --path . --import --quit
```

单纯以 `--headless` 运行游戏不会执行编辑器导入。批量角色和动作重建还需要相应原始素材、Blender／MMD Tools 及各制作脚本要求的 Python 依赖，具体命令见制作指南。

用户种植存档位于 `assets/world/tree_planting/world_edits.json`，应保留并审阅其变动。外部模型、动作与音频的来源及使用条件按各素材记录管理。

旧整图测试已移到工作区外部归档 `D:/Prism Route/archive/legacy_world_tests_20261104/`。项目仍使用名称中带旧日期的部分共享材质与脚本，清理前要检查实际引用。参见 [旧场景归档记录](docs/LEGACY_WORLD_SCENE_AUDIT_1104.md) 和 [逐文件归档清单](docs/legacy_world_archive_1104_manifest.json)。
