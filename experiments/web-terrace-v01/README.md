# Web 曲面群岛建模试验 v01

这是一次独立的浏览器建模试验，用来判断 Web 工作方式能否帮助我们实现参考图中的起伏曲面、拱腹与分叉支承。尺寸和原始地图边界按用户授权放宽；没有导入 Rhino 几何，也没有修改现有 Rhino / Blender / Godot 场景。

## 打开和检查

本机预览：<http://127.0.0.1:8088/>。拖动旋转，滚轮缩放，右键平移。提供总体、道路、桥下、结构视角；白模按钮隐藏环境和植被，便于评价建筑。肩部展开、拱腹厚度参数改变后，点击重新生成。

重新启动：在本目录运行 `node server.mjs`。Three.js 0.180.0 与所需 addons 已随源码保存，不依赖 CDN。需要有 WebGL 的浏览器；不能直接通过 file:// 打开模块网页。

保存到项目按钮通过仅监听本机的服务器，把两个 GLB 与参数统计写到 exports。普通导出按钮仍可供浏览器下载；本次工具未成功捕获下载事件，因此归档使用项目保存按钮。服务器只接受三个指定文件名和本机页面来源。

## 文件

- `model.js`：所有主体建筑几何的生成代码，坐标单位米、Y 轴向上。
- `app.js` / `index.html`：实时预览、材质、灯光、视角、参数及导出。
- `exports/web-curved-architecture-v01.glb`：三个景观体块、斜向道路桥、中央建筑及屋顶装饰。约 30.9 万三角面。
- `exports/web-curved-archipelago-v01.glb`：建筑加道路、地面和环境摆件。海水、天空、预览灯光不在此模型中。
- `exports/build-report.json`：浏览器实际生成耗时、参数与边界。
- `exports/mesh-audit.json`：导出后重新读取 GLB 的拓扑检查。
- `timing.json`：本次任务起止时间与墙钟耗时。
- `captures/01-overview.jpg`、`02-underbelly.jpg`、`03-structure.jpg`：实际 WebGL 画面，未使用生成图替代。

参考为项目中的 [整体效果图](../../docs/concepts/cliff_terraces_2026-10-14/B_interwoven_overview.png) 和 [底部效果图](../../docs/concepts/cliff_terraces_2026-10-14/B_interwoven_detail.png)，也就是用户本次给出的两个方向。

## 几何做法

1. 用带高度与宽度的 Catmull–Rom 路径定义三条起伏景观翼和一条斜向桥。横截面从冠面连续卷向侧边和厚拱腹；不是简单的平面挤出。
2. 支脚使用变半径的曲线体积，脚部收束，颈部倾斜，向上分叉并扩大肩部。支脚与拱腹通过平滑隐式并集合成同一体积；两端用更实的桥台。
3. 用道路走廊体积从建筑中扣出通行洞口。各层仍是独立体块，未做整个场景的全局并集。
4. 浏览器 JavaScript 在体积场内采样，Marching Cubes 转为三角网格；进行位置焊接、微小边界回路修补、Taubin 平滑，并单独平滑着色法线。
5. 暖白外表用 MeshPhysicalMaterial，粗糙度 0.30、clearcoat 0.28，配环境反射与太阳阴影。它是实时 PBR 材质；本次未生成建筑贴图，也未做烘焙。

Three.js 和 MarchingCubes 是现成库。树复用了项目已有 `tree_small_broad_canopy.glb`，车、石头和草仅提供尺度与环境。按照用户要求，这些摆件的精度不参与建模评价。Python 只用于读取导出文件并检查拓扑，没有生成建筑。

## 实际验证

通过浏览器按钮验证四个视角、白模切换、保存；肩部参数从 1.00 改为 1.05 后重新生成，面数随之改变，再恢复 1.00 归档。

GLB 重新读取检查：五个主要建筑网格各有一个连通分量；没有开放边、非流形边或退化三角形，位置与法线有限。屋顶球体的 UV 接缝在按位置合并后的拓扑检查中同样封闭。检查脚本只做读取，不修改 GLB。

早期出现了采样范围截断端部的问题，已通过扩展采样范围解决；还有微小焊接裂缝和独立残片，进行了修补。检查不证明 G2 连续、自交不存在、不同体块之间无重叠，也不证明道路符合游戏碰撞或驾驶要求。

## 效果判断与时间比较

当前已经实现独立的可旋转模型，以及支脚向肩部、拱腹融合的体积构造。但是它没有完整还原两张效果图：整体仍偏三条平行 C 形弧带，缺少参考图更丰富的不对称交织；中央建筑仍过于规则；近景有局部鼓包、折痕和层间穿插。法线平滑能改善高光，不能代替几何曲率质量。它应作为方法原型，不应直接替换项目正式地形。

第一次粗模型可见约用了 12 分钟。完整制作时间以 timing.json 为准，包含依赖准备、编写、预览、视角修正、拓扑修补、导出、截图和记录。默认场景最后一次生成约 2.5 秒，先前迭代约 2–5 秒；这是重新生成的时间，**不是从效果图建模的总耗时**，也不是帧率。

这次能证明浏览器可以独立生成、调整和保存这种网格模型。不能据此证明 Web 一定优于 Rhino / Blender：本次尺寸约束更松，视觉效果也未达到同等质量；网格采样、法线、预览及导出又带来了额外调试。下一次公平比较应该选择同一支承节点、同一边界和目标质量，分别记录达到目标所需时间。

本次文件独立保存在 experiments 中，`.gdignore` 防止 Godot 自动导入。作为方法实验归档，不替换正式游戏地形。
